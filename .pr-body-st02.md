## What was wrong

In his screenshot, a turn opened by another agent's message ("claude-sr2-coord …") sits under its opened "Worked for 7s", followed by "Sent to …". `model.ts` `headsIncomingTurn` gave any notice or message right under a "Worked for" line the head gap (16 px). That gap is for a line that opens the *next* turn under a closed "Worked for". Under an *opened* fold, the message is that fold's own first entry: turns.ts `foldsPrompt` folds the message that opened the turn into its "Worked for". So it stood 16 px under the rule, while every tool row there sits flush on the 22 px pitch.

## Fix

`headsIncomingTurn` now applies only under a closed "Worked for" (`prev.foldOpen !== true`). Under an opened one, the received line gets the gap a tool row gets in its place. Spacing still has a single owner, `transcriptGap`; no new rule was added.

## Evidence (chat simulator, model run)

New scenario `received-sent-as-activity`. A message opens a turn that sends one and replies, and the reader opens its "Worked for". A notice then opens the next turn, which receives a message mid-turn and sends between calls. Each step probes every received and "Sent to" row and checks its gap against the gap a tool row would get under the same row (`transcriptGap(markAbove, MARK_STEP)`):

| before | 16 px (a tool row: 0), steps 23–42 | 0 = tool row |

The simulator's other changes:
- A steered message (`steer: true`) no longer counts as a new turn (direct.ts `startsTurn`).
- A new `b.message(...)` builder adds a message mid-turn.
- A new `reader({ open })` action opens a fold.
