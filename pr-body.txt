## What a new user saw

On the Mac, a Cloud chat's start view names each stage: the machine, the copy, setup, and then "Starting Claude Code · usually a few seconds" (cmux#39492). When the start succeeds, the chat moves to the machine's own chat page (`CloudStartChat.openUploaded`), and that page sends `session/new`. Until `session/new` answers, the queued first prompt showed only an untimed "Thinking" line (`agentStartLook` default, `Thinking.tsx`). The stage the Mac had just named disappeared at the hand-off, so a new user lost track of what was happening right before the first answer.

## Change

A Cloud chat's queued first prompt now keeps the Mac's last line on the machine page:

- It reads **"Starting Claude Code · usually a few seconds"**, with its clock counting from the send.
- After 30 s the usual wait changes to **"taking longer than usual"**.
- It is one live line in the same `cv-worked` box, so the answer's first words replace it in place. There is no Cancel and no layout shift (Leo, 2026-11-01).

Scope and defaults:

- Only Cloud chats are affected (`cloudPreviewChat`); local chats keep their Thinking line.
- The `cloud-start-quiet-look` `thinking` arm brings back the old line.
- No default is flipped, and no string is renamed or removed.

Files:

- `conversation/CloudAgentStartLine.tsx` (new): the line and the context that carries the agent's name.
- `cloudStartViewModel.ts`: `agentStartStage` and `AGENT_START_SLOW_MS`.
- `rows/ThinkingRow.tsx`: branches to the new line while a row is `queued` in a Cloud chat.
- `App.tsx`: one provider around the transcript.
- `cloudStart.css`: three rules.
- One new string, `cloudStart.eta.longer`, in all 21 locales.
- A new gallery entry, `agent-pane.cloud-agent-start`, with 5 variants: just-sent, mid-wait, taking-longer, codex, and thinking-before.

Web only. No Swift or Rust changes, so no fleet Swift compile was needed.

Follow-up, not in this PR: the machine-side phases (acpmux connect, checks, session/new) come back only in `agent-session-start`'s final `timings_ms`. Naming them live would need the Rust daemon to stream them and a machine image roll.
