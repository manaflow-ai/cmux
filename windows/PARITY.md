# Windows parity

This port runs as an Electron desktop application with xterm.js and Windows
ConPTY. It reuses the Windows implementation credited in [UPSTREAM.md](UPSTREAM.md).
It does not execute Apple SwiftUI or the macOS GhosttyKit binary.

## Verified in this checkout

| Surface | Evidence |
| --- | --- |
| Window and pane chrome | Live dimensions match the current Swift constants: 28-point titlebar and pane bars, 240-point default sidebar. Tests read the Swift source so subsequent source changes expose drift. |
| Default appearance | Charcoal sidebar, Monokai terminal, blue workspace selection, compact controls, thin split separators and blue attention treatment compared visually against repository screenshots. |
| Terminal | Real PowerShell command entered through the desktop's xterm input path; output asserted in the rendered terminal. Required native node-pty dependency, bundled ConPTY DLL. |
| Per-split tabs | Create, switch, close selected tab, preserve surviving terminal and split position; six focused model tests plus desktop integration. |
| Nested splits | Right and down splits, all panes visible at 640×480, 1280×800 and 1920×1080; terminal canvas fills the window. |
| Browser | Local fixture page loaded in a real guest, with sandbox enabled and Node integration disabled. |
| Notifications | Runtime notification reaches workspace summary, attention ring and bell count; notification panel opens. |
| Restoration | Full process restart retains workspace, four terminal processes represented by three visible splits, tab membership and nested split tree. Shell processes are recreated on full desktop exit. |
| Display scaling | Desktop integration passes at 100% and 150%. |
| Distribution | `test:packaged` launches the built executable with its in-process runtime and checks native ConPTY, command execution, rendered output and normal close. |

Screenshots are generated by the tests under `test-output/`. They are local
verification artifacts, not pixel-identical macOS golden images.

## Remaining differences

- A running macOS build with identical content, theme, font and scale is still
  needed for paired screenshot comparisons. Zero visual regressions has **not**
  been established. Existing screenshots include user-selected terminal themes.
- Segoe UI/Cascadia and Windows text rasterization differ from macOS fonts.
  Terminal rendering uses xterm.js rather than Ghostty's GPU renderer; image
  protocols, shaping, selection and IME need broader parity testing.
- Tab drag/reorder and moving tab groups between splits are not matched to
  Bonsplit. The inherited optional global tab bar is separate from per-split tabs.
- Windows settings retain the upstream Windows settings UI; the macOS settings
  window and all current right-sidebar tools have not been recreated 1:1.
- The build reuses 195 unambiguous existing messages across nine catalogs/locales;
  Windows-specific copy and dynamically assembled strings still need translation.
  The repository localization checker covers Apple/web catalogs, not Windows UI
  completeness.
- Full macOS CLI/config/keymap compatibility, remote workspaces, updater,
  accessibility, screen-reader and exhaustive browser automation parity remain.
- The distributable is unsigned. The full dependency audit retains eight
  moderate findings in the electron-builder download/proxy toolchain through
  `sprintf-js`; the production dependency audit reports zero vulnerabilities.
- React Doctor reports seven performance warnings and a controlled-search-state
  synchronization warning in imported code; maintainability analysis did not
  complete. These results do not establish a clean full-codebase review.

The macOS/Xcode implementation is unchanged. Windows behavior has its own tests;
passing these checks does not establish macOS app test coverage.

The repository-wide verifier selects every check for the new Windows directory.
Its Unix executable/shebang assumptions prevent the test-wiring-sync tests from
running on Windows, and several unittest receipts fail to recognize Windows
output even when the underlying tests report success. These are not passing
full-preflight results. Portable catalog, policy and schema checks are run
separately with UTF-8 enabled; native macOS build/test coverage remains unrun.
