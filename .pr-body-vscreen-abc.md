Three screen-share faults from a test of the current NIGHTLY on a fleet Mac:

**A. An autoconnect into a background tab never connected.** `cmux tab new-mac-screen --autoconnect true` (or `cmux action run macScreen.open --autoconnect`) into a tab that is not selected waited until the tab was shown, because the hub pane was built only at first show, and `app mac-screens` read it as ended. Now `MacScreenPageService.open` with `focus: false` calls `MacScreenPages.connectInBackground(key)` once the tab exists. That builds the tab's screen and asks the hub right away (`MacScreenPane.requestWaitingScope`, the same request `resume()` makes when the tab is shown). A tab opened without a scope still waits at Connect.

**B. A host Mac with no Screen Recording grant failed silently.** The helper called SCShareableContent and then stopped, and the viewer showed no_frame.
- `cmux-rd-host` now checks the grant at capture start and restart (`permissions::require_screen_recording`). With no grant, the session ends with `Screen Recording not granted on <host>. On <host>, open System Settings > Privacy & Security > Screen & System Audio Recording and turn on "<item>".`, where `<item>` is the capturing helper's own bundle name (for example "cmux NIGHTLY Screen Sharing"), else "cmux Computer Use".
- The reason never reached the viewer, because `cmux-rd-link` dropped control records that were queued before a close. `Command::Close` now flushes them first, so the existing failed card shows "<Mac> couldn't share its screen: Screen Recording not granted on ...".
- `remote-host grants` no longer reads `granted: null` from the app, which is the wrong holder. Each share now runs `<helper> permissions` in the helper's own responsible process and keeps the result in `share-host status` (`helper.permissions`, with `listed_as`). The grants probe reads it first wherever no cmux Remote is embedded, and the fix text names the item that captures.

**C. A static screen had no viewer timings.** With one decoded frame, decode_ms, glass_ms and decode_present_ms were null, because a drawable whose present time macOS did not record (`presentedTime == 0`) was dropped. That frame now reaches the viewer's timings, using the time its presented handler ran. The host still gets only real present times.
