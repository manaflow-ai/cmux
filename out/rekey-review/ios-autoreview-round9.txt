[P1] Wildcard cleanup performs one backup request per sibling
Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/MobileShellComposite+HiddenMacs.swift:267
The tag-less forget loop awaits `deleteStoredPairedMacRow` for every local sibling. In production, each call reaches `BackingUpPairedMacStore.removeExactScope`, which immediately flushes that row's tombstone over the network. A device with many tags/team rows therefore causes one sequential backup POST per row after the broker revoke loop; failed requests can each consume the 5-second timeout, leaving the Forget UI busy for minutes with no cleanup deadline. Batch the local deletions/outbox writes and flush the grouped tombstones once per destination.

[P1] Pending deletes are stored under the wrong scope for mapped team-less backups
Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/BackingUpPairedMacStore.swift:492
`removeExactScope` now keys the pending-delete outbox by the row's team. For a team-less row whose persisted echo maps its backup to team A, a failed initial tombstone upload leaves the intent under `(account, nil)`. Subsequent reads while team A is selected inspect only `(account, teamA)`, so they neither retry nor suppress that pending delete; the next successful team-A restore can immediately resurrect the forgotten row. Persist enough metadata to keep the exact local row scope separate from the resolved backup/outbox destination, and consult that intent during restores of the destination scope.

[P1] Do not re-resolve a team-less delete when its backup mapping is missing
Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/BackingUpPairedMacStore.swift:939
When no mapping exists, this fallback sends a team-less row's tombstone with `teamID: nil`. That occurs for existing installations before a successful echoed fetch/upload, older workers, or accepted responses without a usable echo. The server then resolves the destination from current account/team state, which may differ from where the record was originally stored; the target survives while an unrelated same-pairing record in another team can be deleted. Because the destination is correctness-critical, keep the tombstone pending and recover a verified mapping instead of guessing.

[P2] Propagate wildcard sibling enumeration failures
Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/MobileShellComposite+HiddenMacs.swift:262
A failed cross-team enumeration is converted to an empty list, after which `siblingsCleaned` remains true. Since the account-wide broker revoke has already succeeded, this can report a successful Forget while leaving sibling rows whose bindings were revoked; those dead rows later reappear in another team or restore. Treat the load failure as cleanup failure and surface the existing retryable error instead of silently claiming success.
