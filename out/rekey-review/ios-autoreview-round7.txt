[P1] Do not migrate a backed-up defaults ID onto new hardware
Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/DeviceRegistryService.swift:212
When the device-only Keychain item is absent, this branch adopts the `UserDefaults` mirror. App backups can restore `UserDefaults` onto a different phone, while `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` items do not migrate. The new phone therefore reuses the old phone's device ID, causing both installations to compete for the same `(user, device, tag)` binding slot and overwrite one another. When Keychain authoritatively reports absence, discard the mirror and mint a fresh Keychain ID; use the mirror only while Keychain is temporarily unavailable.

[P1] Capture identity and credentials in one authenticated snapshot
ios/cmuxPackage/Sources/cmuxFeature/MobileIrohRuntimeComposition.swift:2664
The account/generation check and credential read are separated by an await, and `coherentTokenPair()` neither checks `sessionTokenTransitionIsActive` nor revalidates the generation afterward. A sign-out/sign-in can complete while token resolution is suspended, allowing this old-account runtime to return the new session's credentials and perform discovery or relay-policy work against the wrong account. Use `authenticatedSessionSnapshot()` and validate its account and generation, or provide an equivalent atomic auth API.

[P1] Do not permanently invalidate the runtime on foreground revalidation
ios/cmuxPackage/Sources/cmuxFeature/MobileIrohRuntimeComposition.swift:1392
The long-lived token source captures `authSessionGeneration` at activation, but every successful `revalidateSession()` calls `applySignedInUser`, which increments that generation even when the same account remains signed in. `didBecomeActive()` performs this revalidation before using the existing runtime, while auth observation only compares `accountID`, so no reconciliation rebuilds the runtime. After the first ordinary foreground transition, every broker request from that runtime returns missing authentication. Either keep same-session revalidation from advancing this lifetime pin or reconcile/recreate the broker when the generation changes.

[P2] Persist refreshed access tokens instead of minting them per broker request
Packages/Shared/CmuxAuthRuntime/Sources/CmuxAuthRuntime/Coordinator/AuthCoordinator+Tokens.swift:166
`freshAccessToken` delegates to the SDK's explicit-pair helper, which creates a new ephemeral `NullTokenStore`. Once the persisted access token is older than the SDK's 75-second freshness window, this call refreshes over the network but never updates the real token store. The long-lived broker source invokes this path for every request, so subsequent discovery and relay-policy calls repeatedly mint new Stack tokens, adding latency and risking auth throttling. Resolve the coherent pair through the live store with shared refresh deduplication, or persist the refreshed access token atomically.

The synthesized representation of this public struct includes both bearer and refresh tokens, so `String(describing:)`, `String(reflecting:)`, assertion diagnostics, or incidental logging can copy live credentials into logs and crash reports. `AuthenticatedSessionSnapshot` has the same problem and additionally exposes the account ID.
