Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/BackingUpPairedMacStore.swift:71
The backup location is keyed only by `(account, pairingID)`, although the same device/tag can exist in multiple team and client-scope backup collections. An upload or restore in team B therefore overwrites team A's mapping; forgetting the team-A row then sends its tombstone to team B, potentially deleting B's record while A's record survives and restores later. Include the originating local team/client scope in the mapping key, matching the pending-delete scope key.

[P1] Pin broker credential pairs to the activation account
ios/cmuxPackage/Sources/cmuxFeature/MobileIrohRuntimeComposition.swift:1383
This production credential source still calls `currentTokens()`, which this patch itself documents as two independent token reads, and it never verifies that the resulting credentials belong to the `accountID` captured by `activate`. If auth switches while activation is running, subsequent registration/discovery calls can use the new account's credentials with the old account's endpoint state, causing rejected requests or server mutations in the wrong account before the lifecycle revision guard runs. Return an account- and generation-pinned coherent snapshot here, as the new Forget path does.

[P1] Delete wildcard-forgotten rows across every team scope
Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/MobileShellComposite+HiddenMacs.swift:257
A nil-tag forget revokes every binding for the device across the account, but cleanup enumerates only the display team's visible rows and additionally ignores other nil-tag rows. Same-device rows stored in another team therefore retain their local row and server backup even though their binding was revoked; an offline Mac cannot “self-heal,” so the supposedly forgotten computer reappears after switching teams or restoring. Cleanup must enumerate all account-owned scopes, or the server revoke must remain as narrow as the rows being deleted.

[P2] Do not treat a failed legacy-ID migration as durable
Packages/iOS/CmuxMobileShell/Sources/CmuxMobileShell/DeviceRegistryService.swift:216
When `createOrAdopt` fails, this falls back to the legacy UserDefaults value and reports it as durable. That value is still stored only in reinstall-volatile UserDefaults; deleting and reinstalling the app then loses it, mints a different Keychain ID, and strands the existing `(user, device, tag)` binding—the exact failure this change is intended to prevent. The binding activation path should return unavailable and retry until the Keychain confirms the legacy ID was persisted.
