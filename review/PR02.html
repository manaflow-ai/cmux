PR02 — Typed SSH readiness and bounded initial attach

Local proposal artifact · Draft for review · No branch, commit, or public PR

Outcome: password submission produces a working PTY, an explicit retry, or a typed terminal failure. A bootstrap failure cannot be lost because waiter registration ran later, and a never-established session cannot restart an unbounded readiness epoch.

Problem and evidence

  • beginConnectionAttemptLocked performs bootstrap on the coordinator queue. The bridge waiter-registration closure can sit behind it. A bootstrap catch publishes/schedules reconnect but records no terminal outcome; when registration later runs, it parks until timeout.
  • v2WorkspaceRemotePTYBridge gives controller lookup one timeout and coordinator waiting a fresh timeout. The outer CLI has a separate deadline and can expire first.
  • Current NSError/message wrapping erases whether the source was authentication, transient network, invalid release artifact, or deterministic install failure.
  • Initial and known-existing sessions share general reconnect status routing, so bounding the shared loop would regress deliberate persistent reattach.

Production change contract

  1. Add attempt generation plus typed readiness outcome to RemoteSessionCoordinator. Every bootstrap/proxy catch stores the outcome before copying, removing, and completing pending waiters. Registration checks the stored outcome before parking. A new attempt clears only its own generation.
  2. Complete coordinator waiters on terminal failure and stop using the existing first-writer LockedResult and semaphore signal. Never semaphore-wait on the coordinator queue.
  3. At v2 entry create one monotonic server deadline. Controller lookup and startPTYBridgeWhenReady consume the same remainder; zero remainder returns remote_readiness_timeout. No second window.
  4. Use a named 260-second CLI initial policy and cap the app portion at 245 seconds while reserving final connect/ready/attach time. These are UX ceilings sized above the current supported staged path, not hard filesystem maxima.
  5. Classify source errors before broad NSError wrapping. Only unavailable schedules coordinator reconnect. Authentication, fatal, and deadline outcomes do not. CLI branches on v2 code, never message text.
  6. Pass explicit initial/known-existing policy through initial startup, retry builder, restored startup, manual session attach, and runSSHPYTAttach. Initial unavailable retry stays inside one monotonic CLI process; its parent cannot restart the epoch. Known-existing keeps unbounded reconnect and status-252 no-progress cap.
  7. Promote initial state only on proof of bridge-ready: statuses 252/254 or new post-ready indeterminate status 250. Persisted --require-existing, deep-sleep, and moved-surface attach start established; new panes start initial.
  8. For the manifest/dev-selected one-shot bootstrap hello, require name cmuxd-remote and the selected version. Existing mismatch gets one verified reinstall/re-hello; post-install mismatch is typed fatal. Baked/skip-bootstrap proxy hello remains capability-based; explicit dev binary override may retain its documented version exception.

Affected files

  • CmuxFoundation: typed readiness failure, attach policy, and exit/status contract.
  • RemoteSessionCoordinator.swift, +Bootstrap.swift, +DaemonUpload.swift, +PTYBridge.swift: generation/outcome and source classification.
  • Sources/TerminalController.swift: single server deadline and v2 mapping.
  • CLI/cmux.swift, CMUXCLI+SSHStartupScripts.swift, SSHPTYAttachRetryScriptBuilder.swift, SSHPTYAttachStartupCommandBuilder.swift: policy and one initial epoch.

Behavior coverage

  • Failure-before-registration, failure-after-registration, timeout/failure race, next-generation reset, stale lease update, and stop: exactly one completion, no leaked waiter.
  • Fixed clock proves controller lookup consumes rather than restarts the deadline; late controller publication cannot extend it.
  • Network unavailable retries with zero auth; recognized wrong credentials runs exactly one auth attempt; checksum/version/capability fatal runs zero auth and one bootstrap; deadline exits once.
  • Initial unavailable → ready; repeated unavailable → deadline; status 252 cap; 250/254 promote established; restored/moved/deep-sleep policy stays established.
  • Bootstrap hello matching/no upload, mismatch/one repair/success, post-repair mismatch/fatal/no retry, baked acceptance, explicit override exception.

Review blockers

  1. Typed cause is created at source stage, before error wrapping.
  2. One attempt-scoped outcome covers both failure-before and failure-after registration.
  3. Controller lookup and coordinator wait share one deadline.
  4. Initial expiry cannot be restarted by the parent wrapper.
  5. Established reconnect and deep-sleep behavior remain unbounded as designed.
