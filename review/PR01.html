PR01 — SSH TTY confidentiality and input integrity

Local proposal artifact · Draft for review · No branch, commit, or public PR

Outcome: input typed during authentication, bridge readiness, or retry backoff is neither rendered locally nor later forwarded as a remote command. Normal post-ready input, signals, pipes, and exact terminal restoration remain intact.

Problem and evidence

  • The installed CLI was held before bridge-ready under a real PTY: fd 0 retained ECHO=true, and PRE_READY_SECRET appeared in the transcript.
  • The same line, typed before ready, was delivered verbatim to a fake bridge after ready.
  • Three producers generate the vulnerable ssh-pty-attach --wait interval: initial persistent startup, restored/deep-sleep/new-surface attach, and manual existing-session attach.
  • Suppressing echo alone leaves queued-command injection; flushing only at ready cannot erase already-rendered text or prevent stale backoff input from becoming the next password.

Production change contract

  1. Add one shared CmuxFoundation shell-fragment builder; no existing shared fd-0 ownership helper was found. Consume it from CLI/CMUXCLI+SSHStartupScripts.swift, Sources/SSHPTYAttachStartupCommandBuilder.swift, and CLI/cmux.swift::sshSessionAttachStartupCommand. Do not duplicate shell protocols.
  2. TTY branch only: capture immutable stty -g once; define idempotent restore; arm EXIT/HUP/INT/QUIT/TERM/TSTP/CONT handling; then clear ECHO while retaining ICANON and ISIG. Keep no-echo ownership across all retryable child exits/backoffs. Restore only when the complete wrapper terminates.
  3. Perform checked input discard at exactly two ownership boundaries: before each newly launched foreground-auth process, and after bridge-ready immediately before raw attach. Do not flush between password reprompts owned by one OpenSSH process.
  4. In runSSHPYTAttach, separate transport-ready from terminal-input-ready. On TTY stdin, use a checked TCSAFLUSH/raw transition before connected reporting, resize work, or the stdin pump. Failure follows existing detach reconciliation and forwards no input.
  5. Raw exit restores the wrapper's no-echo baseline; wrapper cleanup restores the immutable original before traps are cleared. Auth-signal cleanup terminates/waits for the nested /usr/bin/script tree before restoration and lifecycle reporting.
  6. TSTP restores before stopping; CONT reacquires no-echo before another input owner starts. SIGKILL/SIGSTOP are uncatchable and excluded from restoration guarantees.
  7. Non-TTY stdin: perform no termios operation and no flush; preserve pipe bytes and EOF exactly. Never open /dev/tty.

Behavior coverage

  • One delayed-ready case for each wrapper producer: pre-ready marker absent from transcript and bridge; post-ready marker present at bridge.
  • Markers during 254 reattach and 255 reauthentication backoff remain absent; a fresh password sent after the next prompt is consumed.
  • Wrong-password reprompt inside one OpenSSH process remains hidden and Ctrl-C interruptible.
  • Exact stty -g restoration after success, fatal error, HUP/INT/QUIT/TERM, and TSTP/CONT.
  • Use /usr/bin/script or equivalent controlling foreground PTY for terminal-generated Ctrl-C/Ctrl-Z; assert tcgetpgrp(0) == getpgrp(). Keep openpty for byte/resize checks only.
  • Injected termios failure: no connected report and no pump. Non-TTY delayed pipe data and EOF remain unchanged.

Review blockers

  1. All three producers use the same helper.
  2. Echo stays suppressed across retry backoff; original mode is never recaptured.
  3. Both flush boundaries are checked and no other flush is introduced.
  4. Connected state is reported only after raw ownership succeeds.
  5. Signal cleanup restores before clearing traps; persistent lifecycle IDs are unchanged.

Dependency: none. Recommended landing order: first, because this is the directly reproduced secret-protection boundary.
