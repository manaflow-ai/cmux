# 管理対象 Mac のリレー TLS

[English](relay-tls-enterprise.md)

macOS のネイティブ Iroh リレー接続は、Apple のシステム証明書検証を使用します。
管理者がシステムキーチェーンにインストールし、TLS 用として信頼した組織のルート証明書を
認識します。Zscaler の検査用ルートも対象です。証明書が存在するだけでは信頼されません。

ホスト名、有効期間、証明書チェーン、macOS の信頼制限は引き続き検証されます。
証明書検証を無効化する設定や、macOS が拒否した証明書を受け入れるフォールバックはありません。
公開 CA と組織の CA の信頼ポリシーは macOS が管理し、cmux はルートを別のバンドルに
コピーしません。`SSL_CERT_FILE` と `SSL_CERT_DIR` は、この macOS Iroh ポリシーを上書きしません。

iOS は従来の組み込み WebPKI 信頼ポリシーを維持します。この変更はモバイル接続の Mac 側に
適用され、Mac の証明書が iPhone でも信頼されるわけではありません。URLSession と通常の
WebSocket クライアントの信頼動作、SSH ホスト鍵の検証、Iroh のエンドツーエンドのピア認証は
変更されません。

## 診断と対処

ネイティブリレーの失敗は、macOS 統合ログの `RelayTLS` カテゴリにホスト名、ポート、固定の
原因コードとして記録されます。接続準備エラーにも、取得できれば同じ原因が表示されます。
「設定」→「ネットワーク」にも同じ安全なメッセージが表示されます。再試行中は表示が維持され、
リレー接続が回復すると消えます。URL のユーザー名、パスワード、パス、クエリ、トークン、
未加工のプロバイダーエラーは含まれません。

```sh
log show --last 10m --style compact --predicate 'subsystem == "com.cmux" AND category == "RelayTLS"'
```

| 原因 | 対処方法 |
| --- | --- |
| `UnknownIssuer` | 検査用ルートの TLS 信頼設定と中間証明書チェーンを IT 管理者に確認してください。 |
| `SystemTrustFailed` | システムの信頼制限と証明書チェーンを IT 管理者に確認してください。 |
| `HostnameMismatch` | リレーホスト名と、リレーまたは検査ゲートウェイの証明書を確認してください。 |
| `CertificateExpired` / `CertificateNotYetValid` | Mac の時計を確認し、証明書の更新や修正を管理者に依頼してください。 |
| `CertificateRevoked` | 失効した証明書の交換を証明書の管理者に依頼してください。 |
| `TLSFailed` | リレーまたは検査ゲートウェイの TLS プロトコル互換性を確認してください。 |
| `NetworkFailed` | DNS、経路、ファイアウォール、リレーへの到達性を確認してください。信頼とは別の問題です。 |
| `Other` | TLS が成功しても、リレー認証やプロトコルが失敗している可能性があります。サービスの状態を確認してください。 |

管理者が信頼設定やチェーンを修正した後、再接続するか cmux を再起動してください。
認証情報のエクスポートや証明書検証の無効化を回避策として使用しないでください。
ルートを信頼しても、ファイアウォールや WebSocket を遮断するゲートウェイの問題は解決しません。

## 再現可能な検証

Xcode 16 以降とパスワード不要の sudo を備えた、使い捨ての macOS VM でのみ実行してください。

```sh
python3 tests/relay_tls/system_keychain.py \
  --allow-system-keychain --diagnostics --output relay-tls-results
```

ハーネスは cmux が固定したネイティブフレームワークを使用します。テスト CA を生成し、
インストール前の拒否、システムキーチェーンへのインストール後の Apple と Iroh の検証成功、
ホスト名不一致、有効期限切れ、ルート削除後の拒否を確認します。TLS 上のアプリケーション
データ送信をもって成功と判定し、ネイティブの原因コードも検証します。診断 API がない
旧フレームワークを再現する場合は `--diagnostics` を省略してください。
生成した CA だけを終了処理で削除し、結果とログを
出力ディレクトリに保存します。Zscaler テナント、組織の認証情報、本番リレーは不要です。
