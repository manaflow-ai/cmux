# acpmux time caps

Leo asked for no arbitrary caps: "under extreme conditions, extreme duress, we need to chug along swimmingly". This page lists
every hardcoded timeout, retry, backoff, poll and deadline in `cmux-tui/crates/acpmux/src`. Each row gives the observed p99
beside the value, and a verdict on whether to keep it, derive it from data, or delete it.

Count caps (list lengths, page sizes, slots) are covered by #50450 and `scripts/ci/count_caps.py`: each kept count cap carries
a `Measured:` doc line. This page covers time and retry values only.

How to keep it true: a PR that changes a value in this table updates its row, and gives the new value's basis as p99 × a stated
margin, an adaptive rule, or the external contract it follows.

## Legend
Verdicts: `measured` (value already adaptive or cites a measurement), `derive` (replace with p99 x margin or an adaptive per-peer/per-op formula; `no data` rows say what to log first), `delete` (retry-until-deadline makes it redundant), `keep-external` (provider/OS/protocol contract). DEVIATION: a fifth tag `policy` marks retention and cadence values (TTL, KEEP, refresh, save) that bound no operation; no PR proposed. No row is tagged `delete` mechanically; delete candidates are named in the PR groups where a retry count duplicates a deadline.

Classification is heuristic by name and doc; rows with `no data` are unverified `derive` candidates. Confirm each in its PR.

## Evidence highlights
- Turn wallMs p50 12.3s, p90 190s, p99 1399s (23 min), max 10244s; 9 of 417 over 600s.
- 415 of 433 queued outbox entries retry forever (up to 230 attempts, age to 85.5ks) against one permanent `Permission denied (publickey)`.
- complete 20s cap hit by 1.5% of completions; inbox reader 15s cap truncates ~14%.
- hibernate exit p99 433ms exceeds 300ms KILL_GRACE; 1s shutdown budget hit in 9 of 25 shutdowns.

## Groups (derive/delete, highest value first)

1. **Peer and mesh RPC waits.** peer.rs HANDSHAKE_MOST 300s vs handshake p99 19s; peer_link/peer_paths/peer_dual backoff and probe constants; mesh_read READ_WAIT/ANSWER_WAIT; mesh_relay and mesh_retry; rpc ANSWER_WAIT. Replace with per-peer adaptive RTT/p99 (as silence budget already does); log per-link connect/handshake ms first.
2. **Outbox/delivery retry.** hub/outbox.rs RETRY_DELAYS_SECS and RETRY_FOR_MS 24h, server/outbox.rs ATTEMPT_WAIT 120s, MOVING_*. Make retry error-class aware: stop (or mark `needs_attention`) on permanent refusals such as ssh publickey denied; keep backoff only for transient errors. Fixes 415 stuck entries.
3. **Harness start/stop/shutdown waits.** agent.rs KILL_GRACE 300ms (exit p99 433ms), daemon.rs SHUTDOWN_BUDGET 1s (hit 9/25), agent_host START/ADOPT_HELLO, hub/shutdown.rs drains, hub/cancel.rs, hub/pool START_*. Derive from woke/exit p99, or wait for the process exit signal instead of a timer.
4. **Turn and completion caps.** complete DEFAULT_TIMEOUT_MS 20s and MAX 60s, inbox_reader READ_TIMEOUT 15s, titles, rolling_summary, prompt_coach, away_recap, btw, hunk_summary; turn_cap 20 min, session_move/live_name/transfer_out/move_end turn waits, stalled_turn. Derive from completion p99 (10-18s) x margin; replace turn waits with progress-based liveness.
5. **CLI and daemon-call deadlines.** cli/run/ls.rs, ls_far.rs, ls_ssh.rs, send_relay.rs, daemon_service.rs, acpmux_mcp_* waits; derive from per-peer relay latency (0.4-0.8s) and ls p99; return partial rows with a per-peer status rather than a fixed deadline.
6. **External service calls.** github_mcp/hosted_mcp CALL_TIMEOUT 280s, github_broker, catalog, vault, chatgpt oauth. No data: add duration logging first, then derive.
7. **Inline literals.** The collapsed `N inline literals` rows (50ms/100ms sleeps etc): name them or replace sleeps with event waits. Policy rows: no PR.
