# LongHorizon-Harness でエージェントのタスクを継続する

[English](longhorizon-harness.md)

[LongHorizon-Harness](https://github.com/AMAP-ML/LongHorizon-Harness) は、cmux の
ターミナルで実行できる外部のタスク実行ツールです。導入は任意です。目標を複数の
実行ラウンドに引き継ぎ、各ラウンドを新しいエージェントのコンテキストで開始し、
別の Auditor が結果を検証してから進捗を確定します。cmux はこのループに
ターミナル、ワークスペース、ブラウザ、通知の機能を提供します。この例では既存の
コマンドラインインターフェースを使用します。cmux にハーネスや専用アダプターが
同梱されているわけではありません。

## 状態を管理する役割

| 管理対象 | 管理するもの |
| --- | --- |
| 目標、次の手順、検証済みの進捗、検証の証拠、復旧 | LongHorizon-Harness |
| 設定されたツールを使った、範囲を限定した手順の実行 | 選択したエージェントの実行環境 |
| ターミナルのレイアウト、スクロールバック、ブラウザペイン、通知先 | cmux |

ハーネスの Manager が手順を決め、Executor が実行し、Auditor が実際のファイル、
テスト、アプリの状態を検証します。検証に失敗した結果は次のラウンドの判断材料に
なります。この記録を正しい状態の基準にしてください。ターミナル出力、エージェントの
アイドル状態を示すフック、通知、プロセスの正常終了だけでは、タスクが完了条件を
満たしたとは判断できません。

cmux のセッション復元は、対応エージェントの会話を復元できます。ハーネスの
タスクのチェックポイントを保存したり、外側のループを再開したりする機能では
ありません。子エージェントを単独で再開すると、ハーネスによる次の検証を飛ばす
可能性があります。ハーネスが管理する作業には、その復旧機能を使用してください。
詳しくは [cmux の README](../README.ja.md) を参照してください。

## 範囲を限定したタスクを実行する

ハーネスの[インストールと設定の手順](https://github.com/AMAP-ML/LongHorizon-Harness#one-command-full-visibility)
に従い、対応するエージェントの認証を済ませてください。
ターミナルだけを使うタスクに、コンピューター操作用のプラグインは
不要です。

cmux のターミナルで、専用のプロジェクトのチェックアウトまたはワークツリーに
移動します。目標、許可する変更、具体的な完了条件を記した `task.md` を作成して
ください。最初は、小さな検証用ディレクトリの内容を、ファイルを変更せずに一覧に
するタスクが適しています。プロジェクトの設定を初期化します。

```sh
lh-harness init
```

`init` は既存ファイルを上書きせずに `.lh-harness/config.toml` を作成します。
各役割に、認証済みのエージェントと対応するモデルを選び、タイムアウトも確認して
ください。その設定で試行を開始します。

```sh
lh-harness run --task @task.md --max-rounds 3 --dashboard --dashboard-no-open
```

3 ラウンドの上限は試行の回数を制限しますが、完了を保証したり、費用の総額を
制限したりするものではありません。エージェントは作業ディレクトリ内で動作します。
ダッシュボードはブラウザを自動で開かずに、後で復旧できるようワーカーの所有情報を
記録します。`--no-dashboard` で開始した実行にはその管理情報がなく、ワークベンチでは
読み取り専用の履歴として表示されます。

既定では、実行状態は `.lh-harness/runs/<run-id>/` に保存されます。このディレクトリと
プロジェクトのファイルを一緒に保持し、非公開のログやタスクの状態をバージョン管理に
含めないでください。中断した場合は、ハーネスのワークベンチで既存の実行を確認します。

```sh
lh-harness web --workspace-root . --port 0 --no-open
```

表示されたローカル URL を開きます。cmux のブラウザペインも使用できます。
実行の検証記録を確認し、利用可能な継続操作を使用してください。同じ実行データの
ルートディレクトリを使い、前のワーカーが停止したことを確認してから継続します。
通常、`lh-harness run` を繰り返すと、再開ではなく新しい実行が作成されます。

## タスクの確認が必要なときに通知する

連携スクリプトから、ハーネスが人による確認を必要としたときに、そのターミナルの
ワークスペースへ通知できます。タスクを実行している cmux のターミナルで実行します。

```sh
cmux notify \
  --workspace "${CMUX_WORKSPACE_ID:?タスクを実行している cmux のターミナルを使用してください}" \
  --surface "${CMUX_SURFACE_ID:?タスクを実行している cmux のターミナルを使用してください}" \
  --title "タスクの確認が必要です" \
  --body "継続する前に、ハーネスの検証記録と残りの作業を確認してください。"
```

通知は、ハーネスの実際の状態変化や手動の確認判断に結び付けてください。この例は
通知を送るだけで、ハーネスのフックを導入したり、進捗を確定したりするものでは
ありません。通知に失敗しても、タスクの記録を変更してはいけません。バックグラウンドの
制御プロセスでは、開始時にタスクのワークスペースとサーフェスを記録し、復元後に
再検証してください。サーフェスが見つからなくても、フォーカス中のターミナルへ
通知先を切り替えないでください。

cmux の既存の連携機能は、[通知](notifications.md)と[エージェントのフック](agent-hooks.md)
を参照してください。ハーネスのコマンドと復旧動作は
[上流のリビジョン a1dd930](https://github.com/AMAP-ML/LongHorizon-Harness/tree/a1dd930614972b92361c1b9cd6aac441a6db5a65)
のソースで確認しています。インターフェースが異なる場合は、インストール済みの
バージョンのヘルプを参照してください。
