# nightly.yml: job `nightly-next-one`, steps "Wait for the nearest deltas and the notes fetch" and "Generate Sparkle appcasts (nightly)"

Amends [note-31](../nightly-workflow-notes.md#note-31).

Since ask-1f1e9b8ec5 (2026-11-28; Leo: "well, background + incremental should be on by default"), the feed's first write carries the nearest deltas whenever the prebuild finishes: the release push (presence Worker, poked by publish-upload-next-appcasts.sh and its minute cron) fires when the feed's newest build changes, so a delta merged after the feed never reached a pushed Mac. Measured on run 46095639816 (job 140827486829): deltas-join stopped the prebuild 98 s after it started (it needs ~150-200 s for 3 bases), the item went out full-only (248.9 MB), and the post-feed job then failed to mount the DMG, so the build never listed a nearest delta; the dispatched tail lists one 34-99 min after its dispatch. Now deltas-join gives an unfinished prebuild NIGHTLY_NEXT_PREBUILD_GRACE_SECONDS (150 s) before stopping it, "Generate Sparkle appcasts (nightly)" signs a finished prebuild's deltas into the item (~26 s, run 44921450626), and the post-feed step adds nothing to an item that already lists a delta. The full DMG reaches R2 at most ~3 min later than before (typically ~1 min); a prebuild past the grace leaves the build full-only with the deltas after the feed, as before.
