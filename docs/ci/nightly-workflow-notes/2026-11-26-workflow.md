# nightly.yml `workflow`: notes moved out of the workflow

Moved from `.github/workflows/nightly.yml` to keep it under GitHub's 500 KB workflow file limit
(tests/test_ci_workflow_file_size.py). Each section's number is the `#N` in the job's `# Why:` line.

## 1

Above: `on:`

Publish channels, resolved once in `decide`: `main` publishes cmux NIGHTLY, `rc/**` cmux RC,
`nightly-next` the cmux-next track (own release, Sparkle key and feed, signed as cmux
NIGHTLY; hq#7156), each feed advancing only in its channel. Only main's
promote-nightly-next moves `nightly-next` (release-next environment).

## 2

Above: `push:`

Publish changed main revisions, at most once per NIGHTLY_PUSH_MIN_INTERVAL_HOURS
of published-commit age (see `decide`), while keeping the scheduled cache warm.
Publish every push to a release-candidate branch as the RC channel.

## 3

Above: `NIGHTLY_NEXT_FEED_BASE: https://files-next.cmux.com/nightly-next`

The cmux-next track (branch `nightly-next`). The feed base must never be
main's nightly or RC feed; scripts/ci/nightly-next-guard.py refuses it.
The track's one feed: each build is signed once, as cmux NIGHTLY
(com.cmuxterm.app.nightly), the app the team runs (hq#7156; Leo,
2026-11-05: "THERE SHOULDN'T BE 2"). It keeps "/nightly-next/" in its
path: UpdateFeedResolver classifies the track by it. Release notes sit
beside it.

## 4

Above: `NIGHTLY_NEXT_RETIRED_FEED_BASE: https://files-next.cmux.com/nightly-next/next`

The retired cmux NEXT-identity feed (com.cmuxterm.app.nightly.cmux-next).
It gets no builds, only the handover item that sends a stray install to
cmux NIGHTLY (publish-nightly). The canary verdicts and pulled.json stay
in its folder, where the app reads them (UpdaterService.channelFolder).

## 5

Above: `NIGHTLY_NEXT_R2_BUCKET: cmux-nightly-next`

cmux-next's own version line (CFBundleShortVersionString
<V>-nightly.<build>) comes from cmux-tui/Cargo.toml [workspace.package]
(`scripts/ci/nightly_version.py next-base`), the version the bundled CLIs
print too; main's nightly and RC keep the project version.

## 6

Above: `NIGHTLY_NEXT_SPARKLE_PUBLIC_KEY: IOPItMLjtc4NsROTNZ6a/jsUW+C4fcicl6SNjVVvzRM=`

SUPublicEDKey of the cmux-next track. The build refuses a
SPARKLE_NEXT_PRIVATE_KEY that does not derive this public key.
