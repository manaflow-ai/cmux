# nightly-next-one: one push slot per signer Mac

Where: `nightly-next-one`'s job-level `concurrency.group` (the push slot; note-19, note-33).

One shared group for two slots (2026-11-27 to 2026-11-28). cmux#62030 put every push back in the one `nightly-next-one-push` group while `vars.NIGHTLY_NEXT_SLOTS` stayed 2, so main's rolling rule promoted a second head that then waited at the shared slot for the whole first build, the case nightly-next-tick.yml warns of ("with the legacy single push group, 2 promotes into a pending run that waits out the whole build"). Over 21 push runs from 2026-11-27 22:10Z to 2026-11-28 13:57Z, nightly-next-one waited at the slot a median 19.2 min and up to 53.1 min (run 46128617386) before starting; run 46151824082's job, pinned to ultra1, waited behind run 46146914237's on cmux15. Per-host groups are back. What stays locked: each Mac runs one build at a time (hold-the-whole-mac and one group per host), the feed write is under the shared publication lease with its build-number and ancestry compare, and nothing is ever cancelled. Leo's later ask names both Macs: "within 30 minutes should be too with the fleet and the Ultra, publishing and notarization included". Detector: `tools/now` deploy-lag rows, and the slot wait (nightly-next-one `started_at` minus `created_at`) on push runs.
