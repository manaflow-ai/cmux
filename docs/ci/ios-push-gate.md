# Push delivery without phone hardware

The cheap server detector is `cmux-next-ios/backend/test/apns-delivery-gate.test.ts`:
`cd cmux-next-ios/backend && bun run test --config vitest.push.config.ts`.
It runs production `sendApns` and ES256 signing against an in-process HTTP-boundary
mock. The mock verifies signatures, destination, headers, payload size, and routing,
then models APNs collapse by device, topic, environment, and collapse ID. It checks
latest-turn replacement, preservation of separate sessions and questions, and
endpoint refusals. It does not contact Apple or prove HTTP/2 delivery. The normal
Worker test suite also discovers this file.

The initial headless receipt ran six tests in 45.30 seconds wall time, 10.86 user
and 11.34 system CPU seconds on the lane Linux host (`time -p bun run test --config
vitest.push.config.ts`). Dependency installation is excluded. The Node Vitest
runner avoids database/Worker bootstrap; server-only PRs need no Mac.

The fleet entry point builds the exact head and owns simulator cleanup:

```sh
cmux-ci run --class simulator --script scripts/ci/cmux-next-ios-sim.sh --ref SHA \
  --arg shots --arg push-gate=1 --sim-features push \
  --artifact artifacts/ios-sim/evidence.zip
```

This first-build verification is separate from the fast headless PR gate. Its
receipt includes the actual simulator result and build cost; dispatch is not a pass.

The simulator detector is `scripts/ci/ios_push_sim_gate.py`. It injects production
APNs payloads through `xcrun simctl push`, requires their unique event markers in
a real notification banner, taps each banner, and requires a new
`debug.open-marks` cycle with `notification_tap`, `route_opened`, and either
`chat_composer_ready` or `terminal_ready`. A successful `simctl` command alone
never passes. Cases cover foreground delivery and background tap-to-wake.

Run it inside an existing fleet simulator lease with the exact-head Demo app
installed and a warm, booted simulator with push services enabled. The caller
owns simulator acquisition and cleanup. The script never boots, builds, or
chooses a simulator itself. The fleet build receipt must bind the installed app
to `--sha`; this argument records that receipt's source, not an independently
verified hash of the installed app. Use an isolated test simulator: the script
relaunches the supplied bundle in mock-auth mode and answers notification
permission and mock-team setup prompts.

Generate two fresh payloads with the production payload builder:

```sh
cd cmux-next-ios/backend
bun scripts/push-gate-payload.ts push-gate-<run-id>-foreground > /tmp/push-foreground.json
bun scripts/push-gate-payload.ts push-gate-<run-id>-background > /tmp/push-background.json
```

From the repository root on the leased fleet Mac:

```sh
python3 scripts/ci/ios_push_sim_gate.py \
  --udid "$LEASED_UDID" --sim-set "$LEASED_SIM_SET" \
  --bundle "$DEMO_BUNDLE" --sha "$BUILD_SHA" \
  --foreground-payload /tmp/push-foreground.json \
  --background-payload /tmp/push-background.json \
  --output artifacts/ios-sim/push-gate.json
```

Each payload must target Demo's `mac-studio` / `mock-t-claude` session and have a
different event ID visible in its alert. The script passes the generated bytes
unchanged to `simctl` and records their SHA-256. Existing matching banners,
missing marks, wrong triggers, and stale cycles fail. The permission primer
(`CMUX_MOBILE_DEV_SERVICE_PUSH`) posts a local setup alert with its own random
marker and no `cmuxMobile` event. Observing it proves notification permission
has completed before remote injection; it cannot satisfy either tested push's
marker or route to the test chat.

For the fleet runner's private device set, `--sim-set` supplies `simctl --set`
and `CORE_SIMULATOR_DEVICE_SET_PATH` to AXe. A fleet run must verify that its
installed AXe can observe that private device; inability to observe it fails
the detector rather than falling back to another simulator.

The total default deadline is 150 seconds, including launch/setup and both
cases; it is a bound, not a measured runtime. JSON records delivery latency,
the app's own route/readiness timing, wall time and driver CPU seconds on both
success and failure. Driver CPU excludes Simulator services and app CPU; do not
report it as total simulator cost. A warm-simulator receipt is needed before
claiming this check's measured PR cost. Headless sender tests run separately so
PRs that only change server sending do not need a simulator boot.

Limits: this checks unsealed notifications and normal banner taps, not Apple's
real APNs authentication/network/delivery, radio behavior, or the Notification
Service Extension process lifecycle (which `simctl push` does not invoke).
Background wake here means resuming the existing app by tapping a banner, not
silent background push or a killed-app cold launch. Keep occasional real-device
sanity checks for those differences; they are not PR gates.

The harness's negative cases run on Linux:
`python3 tests/test_ios_push_sim_gate.py`. These validate the detector, and are
not evidence that the simulator flow passed.
