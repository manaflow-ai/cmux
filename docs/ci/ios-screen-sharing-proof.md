# iOS Screen Sharing proof

Leo: “the buttons are a future optional potential; the other ways (command palette and chevron) shoukd work still. and the protocol should be good still. across ios too.”

This manual proof exercises the iOS app in a new simulator and a physical managed Mac running an unchanged, completed capture bundle from the same source. It does not prove a physical iPhone. The optional Session Info buttons and the old live UI test rig are outside its scope.

The protected capture workflow owns dispatch and account delivery. It must verify a landed full cmux `source_sha`, completed `mac_job`, and its `artifact_sha256` before executing this harness. There is no credential workflow in this repository. Admission requires a dedicated owned Mac under a whole-host exclusive, time-limited lease; a GUI token alone does not admit the proof. Missing admission ends the attempt before sign-in.

Only the approved staging Cloud test account may be mapped to `CMUX_UITEST_STACK_EMAIL` and `CMUX_UITEST_STACK_PASSWORD`. The separate dogfood account is outside this proof's scope. The host launches unchanged with `--cloud-backend staging`, and its bundled resolver must confirm the staging environment and development Stack project before credentials are used. The phone uses the Demo configuration, whose DEBUG sign-in uses that same development Stack project and staging Cloud API.

The harness expects the protected HQ `ios-screen-sharing-proof.yml` workflow on `main`, `GLAEDA_JOB_CLAIM=exclusive`, the runner hook digest, `GLAEDA_CAPTURE_LEASE_ID` and `GLAEDA_CAPTURE_CLEANUP_PATH`. HQ validates the lease ID against its admission receipt before delivering credentials. The private workspace is created beneath that receipt's durable lease directory, with canonical path, owner and permissions checked; Actions temp/workspace and system temporary directories are refused. Only the app control socket may use a separate short temporary directory, removed after its owned process group exits. Those environment checks are defense in depth; they do not acquire a lease and must never be fabricated for an SSH invocation. HQ workflow source and cmux application source are separate bindings.

The runner must have Secure Enclave support, an installed fleet artifact client and `axe`, and the existing screen-recording/accessibility grants. The proof does not grant permissions, change a keychain search list, re-sign the Mac app, or add a software device identity. A reused capture tag with a prior device identity or restored account is refused. Use a fresh run-owned capture tag when building the artifact.

The simulator starts from Settings and taps Screen Sharing and the exact unique host row. Host approval is setup. Success requires the bound session to connect, positive video FPS, OCR of the host InputProbe title in the phone's captured pixels, a fresh random key challenge delivered from the phone's software keyboard to the host probe, and mounted Close followed by no host session. Stop during cleanup cannot satisfy the Stop phase.

The first host launch receives no credentials. After signed-out readback, `debug.cloud.capture_prepare` claims the raw bundle's auth namespace and `debug.device_hub` with `capture_prepare` claims the resolved hub namespace. `debug.remote.capture_prepare` also claims the detached worker identity and raw bundle relay namespaces, bound to the admitted lease ID, raw bundle ID and absolute private HOME. All three claims must succeed before stopping that process. A second launch with the same private HOME and no credentials must read back signed out, then call `debug.remote.capture_resume` with the original binding. Only the exact `ok: true`, `code: remote_capture_resumed`, `lease_bound: true` response admits progress. The harness stops that second process before a third launch receives credentials; an unexpected restored account is preserved and fails the attempt. Remote RPCs allow 80 seconds for the daemon's bounded drain and exit verification. `HostTests.test_credentials_wait_for_all_namespace_claims` detects credential delivery before successful fresh-process resume; `test_remote_resume_requires_exact_typed_lease_acknowledgement` rejects malformed acknowledgements.

Cleanup requires sign-out readback, then `debug.remote.capture_cleanup` proving lease ownership, worker and descendant exit, and namespace absence. Only then may `debug.cloud.capture_cleanup` remove auth stores and device `capture_cleanup` remove app identity and relay stores with `hub_quiescent: true`. Every absence and exit field must be the boolean `true`; removal counts must be nonnegative integers. A remote that never started must explicitly return `no_remote_started`, `worker_started: false` and zero removal counts, with the same ownership and absence proofs. A missing or malformed remote proof preserves the app ownership markers and fails cleanup. Both app and input probe launch in their own process groups; stopping the parent alone cannot certify that their children exited. Private HOME and simulator removal must also be verified before release. These remote methods remain a deployment dependency until their implementation lands; portable consumer tests do not establish runtime support.

Only the allowlisted receipt is archived. Account/device identifiers, raw screenshots, app logs and input logs stay in the private workspace. Verified host cleanup permits workspace removal; failed cleanup retains it on the quarantined host so its lease markers remain available for recovery. Cleanup is reported only after the run-owned workspace has been removed and its absence read back; a failed removal or surviving private HOME cannot release the host. A missing archive, queued job, timeout, or partial phase is never a successful proof. `tests/test_ios_screen_sharing_proof.py` detects false success from blank video, stale input, surviving sessions, failed cleanup, erased recovery markers, surviving private files, wrong artifacts and unsafe receipt values. The workflow is an explicit manual proof, not a new PR CI gate.

Fixture isolation: allocate each fake app and HOME below a test-owned TemporaryDirectory; even mocked commands must not share predictable paths. The test-determinism detector enforces this. The workflow-ref fixture tests admission identity without reading workflow files and remains registered as manual. The fleet Keychain detector distinguishes only a literal four-argument attributes probe from secret reads; extra flags, mutable argv and unknown wrappers remain findings, covered by its Patterns regression. Remove existing allowances when that classification makes them obsolete; the fleet rule lint detects stale entries.

Process cleanup tolerates permission-denied signals because macOS can return EPERM for a zombie-only group, then independently reads the owned group state. An unreadable state or any live survivor still fails cleanup and preserves recovery markers. `HostTests.test_permission_denied_signals_require_group_absence` covers both outcomes; `test_ci_killpg_tolerates_eperm.py` checks signal-handler coverage.
