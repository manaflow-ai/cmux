# Cloud ターミナルへの画像貼り付け

管理対象の Cloud ターミナルで Cmd+V を押すと、準備済みの画像が認証済みの
cmux-tui 接続で VM に送られ、リモート側のファイル名が貼り付けられます。
デーモンのブラケット付き貼り付け処理を使うため、Codex と Claude は VM 上の
画像を読み込めます。Mac 側のファイル名は Cloud のプロセスに送信されません。

既存の `TerminalImageTransferPreparationService` と分離されたクリップボード
準備ワーカーを再利用します。転送は `CloudTuiManualMirrorSession` が所有する
認証済み接続とアタッチメントのリースに限定されます。公開アップロード先、
シェル経由の受信処理、プロバイダーの exec、追加の認証情報は使用しません。
プログラムからのクリップボード照会（OSC 52）では画像を転送できません。

## 互換性

デーモンの `identify` 応答には **`terminal-image-paste-v1`** とリース付き
アタッチメントのサポートが必要です。これは mux プロトコル 12 への追加機能で、
プロトコル番号が 12 でも、この機能がない古いデーモンには対応しません。
更新後はターミナルを再接続してください。古いデーモンでは更新を案内し、
Mac のパスを代わりに貼り付けることはありません。Linux、Android、Apple の
デーモンがこの機能を通知します。

ローカル、SSH、リモート tmux、Ctrl+V のキー送信、ドラッグ＆ドロップ、iOS の
既存の処理経路は変更しません。通常のテキストも従来どおり貼り付けます。
コマンドバッファの Cloud 画像添付は未対応です。バッファの送信前に添付を
送らないよう、ターミナルへ直接貼り付ける案内を表示します。

## 制限とクリーンアップ

- PNG、JPEG、GIF、WebP のみで、1 画像あたり 20 MiB までです。双方で内容の
  シグネチャを確認します。Mac のファイル読み込みはメインアクター外で行い、
  サイズを制限した通常ファイルの読み込み前後にキャンセルを確認します。
- 48 KiB ごとに受信確認を待ち、転送は 120 秒でタイムアウトします。既存の
  進行中表示とキャンセルボタンを使います。確認待ちは高遅延回線の速度を
  犠牲にしますが、メモリ使用量と順序を制御できます。転送は bulk レーン、コミットはキー入力と同じ順序付きレーンを使います。
- 接続ごとに 8 画像、デーモン全体で 32 件、予約済み容量は 128 MiB までです。
  転送開始時に申告された全容量を予約し、復旧したファイルも制限に含めます。
  削除に失敗した場合も容量の予約を保持し、再試行で安全に削除できるまで
  その転送への追記やコミットを拒否します。
- デーモンが一時領域にランダムな専用ディレクトリ（0700）と画像ファイル
  （0600）を、検証済みのユーザー専用領域に作成します。安全でない一時ディレクトリは
  拒否します。通常、エージェントは同じ Unix ユーザーで動作します。
  リクエストでは保存先パスを指定できず、確認応答にもパスは含めません。
- 接続のリース、公開ターミナル ID、サーフェス、ワークスペースの所有関係を
  確認します。再接続や置き換え、ワークスペースの変更では転送を中止します。
- 未完了の転送は 2 分後、切断時、またはキャンセル時に削除します。貼り付け済みの
  画像は再接続後も読み込めるよう 10 分保持し、ターミナル終了時にも削除します。
  ビューを閉じるだけでは削除せず、ターミナル本体の終了では最終画面を保持する場合も
  削除します。同一ターミナルに複数の有効なビューがあっても貼り付けられます。
- 同期済みの専用所有権記録により、デーモンのクラッシュ後も復旧できます。
  再起動時に inode とファイルの永続的なランダム所有権マーカーを確認します。
  inode が再利用されても置き換えられたファイルを削除しません。一時領域には
  拡張属性のサポートが必要で、安全な所有権記録を保存できなければ転送を拒否します。
  作成から 12 分（転送 2 分、読み込み 10 分）で期限切れとなり、64 件ずつの
  継続的なスキャンで削除します。一巡後は 30 秒ごとに再走査し、一時的な削除失敗は
  記録を残して再試行します。停止中の VM は再起動時に期限を確認します。
- 所有しているファイルだけを削除します。置き換えられたファイルやシンボリック
  リンク、無関係なユーザーファイルを残し、ディレクトリを再帰削除しません。
  所有権を確認できない場合はファイルの保全を優先します。所有権記録の作成前に
  残った空ファイルにはクリップボードの内容は含まれません。

コミット前のキャンセルではパスを貼り付けません。コミット開始後に確認応答が
失われた場合は結果が不明なため、再試行前にエージェントの添付を確認するよう
案内します。自動再試行はしません。複数画像は個別に転送するため、後の画像が
失敗した時点で前の画像が添付済みの場合があります。

OS 上のセキュリティ境界は VM の Unix アカウントです。同じアカウントで動く
別のエージェントはファイルにアクセスできます。既存の Cloud ファイル操作と同様、
セッションやリースの検証はエージェントごとの OS サンドボックスではありません。

画像内容と元のパスは診断ログに含めません。エラーは Mac の対応する 9 言語で
表示し、管理者によるファイル転送の制限も適用します。

## 検証

経路、順序、機能判定、キャンセル、切断、結果不明、形式・サイズ、所有権、
容量、期限、クラッシュ復旧、ユーザーファイルの保全をテストします。
デーモンのテストでは実際の `Surface.write_paste` のブラケット付きバイト列と、
生成されたファイルを読み込めることを確認します。

cmux-tui はホストされた環境で検証してください。

```sh
./scripts/verify-cmux-tui-hosted.sh --filter cloud_image_paste
```

実機検証には承認されたタグ付き Cloud ビルドを使い、Mac でコピーした画像を
管理対象の Cloud ターミナル上の Codex と Claude の両方へ Cmd+V で貼り付けます。
単独のローカルデーモンのテストだけでは、実際の認証済み Cloud 経路の検証には
なりません。詳細と関連 issue は [英語版](cloud-image-paste.md)を参照してください。
