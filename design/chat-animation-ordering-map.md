## B1. Symptom: scroll up then back down replays an animation

Ranked.

1. **`enteringRows` has no arrival-to-mount bound (high confidence).** Rows that arrive while the reader is beyond the warm window (`WARM_VIEWPORTS`, `VT:1180`) are put in `enteringRows` (`VT:2886-2889`) but never mount. The set is only cleared on mount (`onEntered` `VT:2903`), page hidden (`VT:2752`) or session switch (`VT:2733`). When the reader scrolls down they mount for the first time and play `acpmux-row--message-enter` / `acpmux-row--enter` (`VT:664-670`), minutes after they arrived. The comment at `VT:2719` acknowledges the case and only handles hide/switch. The sibling registries have the bound (`LOAD_FADE_MOUNT_MS`, `shared/loadFade.ts:20,78`) and the older-fade consumes eligibility before paint; `enteringRows` bypasses both. `readerIsMoving` (`VT:2847`) only protects a wheel in progress, not a reader parked above.
   - Fix: store `Map<frameKey, performance.now()>`, and in `drawRowFrames` (`VT:906`) treat `enter` as true only when `now - arrivedAt <= ENTER_MOUNT_MS` (about 250 ms, same as `LOAD_FADE_MOUNT_MS`); prune stale entries each render. Rows that mount later draw whole. Or, simpler: also drop a pending key in the render when its row index is outside `mountedRanges` and the reader is not following.
   - Test: happy-dom under `webviews/test/transcript-load-fade.test.tsx` style: mount 200 rows, scroll to the top, push 3 rows (assistant + tool + line), scroll to the bottom, expect no `.acpmux-row--enter`/`--message-enter`. Currently no test covers this (`transcript-fold-anchor.test.tsx:273` only asserts zero enter rows in a fold).
2. **Held folds close on return and play the turn-end fold (high, by design).** `App.tsx:3178-3184` closes a held Worked when the reader is back at the latest row and sets `heldWorkedClosing`, which makes `VT:3725` capture and `VT:5438` play a full turn-end fold. That reads as "an animation replayed on scroll back" for a turn that ended while away. Held calls/runs (`App.tsx:3160-3170`) release without any fold at all (rows regroup under a tail glide). Fix, if Leo wants no replay: when the reader returns and the held turn ended while they were away, close held Worked at once (`pageAway`-like path: skip `captureTurnEnd` when `closingHeld`) and keep the fold only for folds that closed while the reader watched. Test: `turn-end-hold.test.ts` extension plus `agent-pane-fold-keeps-place.test.ts`.
3. **Live line re-entry (medium).** `VT:2862-2866`: `liveBefore` only protects when the live line was the previous last row. If a notice/compaction row came after it, the live line "arrives" again and takes the `row--enter` fade (O24). Fix: remember the live line's key in a ref (set when first known) and skip when `knownRows.has(key)`, instead of comparing with `previous.at(-1)`.
4. **CSS animations on mount (low).** `cv-needs-input-asked` (`conversation.css:7820`) plays on every mount of the glyph. Fix: class only on the transition (state flag), not on mount. Text reveal, `useFold`, `loadFade` and `older` do not replay (initial state seeded from the current value: `RM:71`, `F` `played=useRef(open)`).

## B2. Symptom: animations sprint

Ranked.

1. **Turn-end fold timer is wall-clock from creation, not from the first frame (high under load).** `TEF:720`: `fold.timer = setTimeout(settleTurnEnd, ms + 50)` at `playTurnEnd` time. The fold's clock starts at the first painted frame (`TEF:390`). `entranceClock.ts:3-15` documents first frames 130 ms or more after the commit on a busy WebKit thread. 180+50 ms from creation, minus a 130 ms late first frame, leaves ~100 ms of the animation played when `settleTurnEnd` calls `animation.finish()` (`TEF:316-327`): the rest of the move jumps. Same shape at `TEF:511` (`grew` re-arm, `ms + 50` from the pass). Fix: arm the timer from the first frame callback (`startedAt`) with `+ ms + 50`, or listen to `animation.finished` for all animations and settle on that, keeping the timer only as a hidden-page backstop (`pageReveal.ts` already finishes on hide). Test: frame test with a stalled first frame (`agent-pane-turn-end-motion.test.ts` busy-main-thread harness): assert no frame moves more than the 0.6 line bound.
2. **Reveal drain at tool boundary and after a stall (high, felt as "sprint for no reason").** `SR:charsPerSecond` `drain` branch: when `done` (the reply row's `streaming` goes false on the next tool call, `endAssistantSegment`) or `stalled` (>600 ms between deltas), the remaining backlog is revealed linearly over `finishMs = 180 ms`. A backlog of 600 ms of text then shows in 180 ms: a visible rush every time a tool call begins or the model pauses. Fix: drain at `max(rate, backlog / drainMs)` with `drainMs` scaled from backlog (e.g. `clamp(backlog / (3 * rate), 180, 600)`), so a moderate backlog finishes at about 3x the stream rate, not 10x. Test: unit `streamReveal` (there is `saidReveal.test.ts`; add one for the max chars/frame at stall).
3. **Arrival step shortened by "left" (medium).** `FC:644`: a pass during a step keeps the step's remaining time as `floor` of `arrivalStepMs`, and `from` is the whole new offset: when the measured height lands a pass later with 2 ms left, a 20 px move plays in `max(2 ms, frames*8.3 ms)`, about 20 ms. Fix: floor = `MOTION_MS.quick`-share by the new px, not the leftover time (or keep the leftover only when the new offset is under the old one). Test: `row-arrival-settle.test.ts` with a second pass at 70 ms.
4. **`FRAMELESS_MS` and `CHASE_MAX_LAG` land at once (medium).** `FC:374`, `:582`, `:598`: a frame requested 150 ms ago and not run (a long task, e.g. the row-mount burst when scrolling back) makes the whole held move land in one frame. Fix: clamp `dt` and keep a bounded-step catch-up (already done by `MAX_STEP_S`) instead of `stop()` unless the page is actually hidden (`document.visibilityState`/`pageAway`). Test: `chat-scroll-back-still.test.ts` style with a 200 ms long task.
5. **Settle on dropped frames (by design).** `F:157-187`: two consecutive 50 ms gaps land a height fold at once. Lower priority; it is the intended load fallback.
6. **Fold retarget joins mid-clock (O12) and `grew` (O11)** are deliberate, bounded by the 0.6 line frame test (`turn-transition-jumps.test.ts`); not root causes alone.

## B3. Symptom: messages above the newest wholly re-render

Ranked.

1. **`RowContent` memo compares `row` by object identity; a regroup that rebuilds rows re-renders every mounted row's content (high that this is what a rebuild does, medium that it is the one Leo sees).** `VT:422-437`: `Object.is(previous.row, next.row)`. `shapedTurn` caches by source-row identity and `last` (`turns.ts:1133-1155`); when the source rows are cloned (the comment at `virtualTranscriptModel.ts:57-58,88-89` says "snapshot rebuilding clones unchanged rows when a prompt is sent") every turn misses, so all turns produce new row objects. `RowFrame` is protected by `sameRowDraw` (id/at/version/below/ended) but `RowContent` is not: each Component runs again (renderer memo is the only guard). Also `cached.last === last` (`turns.ts:1140`) rebuilds the previous turn every time a new prompt is sent (O27, bounded). Fix: compare `row` in `RowContent` with `sameRowDraw` for kinds whose renderer does not read fields beyond the version, or ensure `direct.ts` keeps the object for unchanged rows (no clone when only `below`/`lastTurn` differ). Test: extend `agent-pane-scroll-tick-renders.test.ts` / `acpmuxPerf.render("content:...")` counters: send a prompt in a 30-row chat, assert `content:` renders for rows above the last turn == 0.
2. **Frame-key remap when message ids change (high when it happens).** `VT:931` key is `${frameKey}:${rowFrameKey(row)}`; `adoptFrames` (`direct.ts:2420`) preserves the frame only when the new row's words match a gone row's (`sameWords`). A reply whose id is its first chunk (`direct.ts:2406` comment) and that is rebuilt after streaming more text, a reconnect replay, or an older page remounts: unmount, `message-enter` fade (the "showing and hiding" Leo reported 2026-11-11). Fix: derive assistant-row ids from the turn id + ordinal (stable across rebuilds) so no adoption is needed. Test: `message-run-keeps-frame.test.tsx` style: rebuild the same chat under new reply ids, assert the DOM node identity is the same.
3. **`RowFrameCache` shared-input invalidation (medium).** `VT:880-897` `cache.begin([...])`: any change in `registry`, `rowWidth`, `observer`, `queueDrawn`, `onOpenDiff`, `streams`, `sessionId` clears the whole cache and rebuilds every frame element (`rowFrameCache.ts:80-83`). The reader sees all rows re-render (not remount) together, e.g. when the scrollbar appears as the content outgrows the viewport (`rowWidth`) or when `streams` flips at turn end. Fix: record which input changes in a dev counter (`acpmuxPerf`), and keep `rowWidth` changes to whole-px steps. Test: count `row.renders` before/after a turn end in a gallery frame test.
4. **Turn end id rename (by design, animated).** `WORKING-x` -> `WORKED-x` (`TEF:140`) and the edits card taking the first edit's id (`TEF` comment at `:140`) remount those rows; the fold plays over them. Not the "messages above" case.
