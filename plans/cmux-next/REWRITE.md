# cmux next: Swift frontend rewrite on cmux-tui

Living document. Branch `feat-cmux-next`, worktree `worktrees/feat-cmux-next`.

## Goals (user, 2026-09-28)

1. Remove bonsplit entirely.
2. Terminals and layout state live in the cmux-tui daemon. Quit and reopen cmux keeps every terminal, tab, pane, column, screen, workspace.
3. Tabs: Chrome-style. Tabs shrink as count grows, hover a tiny tab for a live preview, Chrome-level open and close animations. Also a bonsplit-like mode.
4. niri-style scrolling columns: create columns, scroll horizontally between them.
5. Screens: supported, UI hidden until the user opts in.
6. Command palette (Cmd-Shift-P): Raycast quality, Liquid Glass, fast fuzzy search, every action registered.
7. Sidebar: Arc/Dia/Chrome quality, Liquid Glass, better drag reorder, groups.
8. Browser: WebKit and CEF (patched fork with real Chrome extensions). POC ~/fun/cmux2, fork ~/fun/cef-cmux, dist ~/fun/cef-cmux-dist.
9. Delete and rewrite. Do not port old Swift. Modern Swift 6 / AppKit / Observation. Move state into cmux-tui where it belongs.

## Tab drag (user requirement 2026-09-28): as fluid as possible

One drag, every destination. Dragging a tab can end as: reorder in its strip; move into another pane's strip (any window); new split (pane edge zones L/R/T/B); new pane in a column; new niri column (between columns or past the last column); new workspace (sidebar gap, or onto the sidebar "new" zone); move into an existing workspace (hover a sidebar row, Arc-style spring-load: hovering opens that workspace so you can keep dragging into its panes); new window (release outside any window: Chrome tear-off, the window appears under the cursor already carrying the tab).

Design:
- `TabDragSession` lives in CmuxNextApp (the only module that sees every surface). It owns one floating borderless panel with a live glass "ghost" of the tab (thumbnail from the terminal/browser snapshot API) that follows the cursor across windows and outside them. Chrome behavior: while over a tab strip the ghost collapses into an inline tab with neighbors sliding; when it leaves the strip it expands into a preview card; over a pane it shows the drop-zone highlight.
- Each surface implements a `TabDropTargetProviding` protocol (in CmuxNextDesign so every module can conform without importing each other): hit-test(point in screen coords) -> DropProposal(kind, highlightFrame, commit closure). Tab strip, layout, sidebar conform; the window background and "outside" are handled by the session.
- Commit is ONE daemon command per outcome (atomic, undoable): move-tab(to pane, index), tab-to-new-split(pane, edge), tab-to-new-column(screen, after column), tab-to-new-workspace(group?, index), move-tab-to-workspace. Windows are frontend-local: which workspace each window shows persists in a `personal` frontend projection so windows restore after relaunch. Tear-off = tab-to-new-workspace + open that workspace in a new window.
- Optimistic UI: apply locally at drop, reconcile via transaction-id echo. Escape cancels with a spring back to origin. Spring-loaded sidebar hover 500 ms. Auto-scroll strips, sidebar and niri columns near edges during drag. Multi-tab drag (cmd-click select) later.
- Tabs (PR 15509, merged): App must end every drag (model removal or restoreDetachedTab) or the tab stays hidden. Optimistic reorder is kept until model order changes: on daemon rejection the App must push the authoritative order (transaction-id echo) to reset it. Rename the App's placeholder TabStripView.

## Action contract (user requirement 2026-09-28): every feature, every entrypoint

Every user-visible capability is ONE `ActionDescriptor` in CmuxNextActions plus ONE handler. Entrypoints are generated from the registry, never hand-wired per surface:

| Entrypoint | Generated how |
| --- | --- |
| Command palette | lists every available action; args collected inline from the action's argument schema |
| Keyboard | every action is bindable; default shortcut optional; user bindings in cmux.json `shortcuts.<actionID>`; Settings shortcut editor lists the registry |
| Right-click | menus are declared as ordered lists of action IDs per context (tab, tab group, pane, column, workspace row, workspace group, sidebar background, terminal selection, browser page, link); the menu builder renders title/shortcut/enabled state from the registry |
| CLI | `cmux action list [--json]`, `cmux action run <id> [--arg k=v ...] [--target ref]`; plus a friendly generated verb per action (`cliName`, e.g. `cmux tab-group create --name X`), all over the app control socket (`action.list`, `action.run`, `action.describe`) |
| Menu bar | main menu built from action IDs too |

Descriptor fields: id (stable, = cmux.json shortcut key), title (localized), keywords, category, symbol, argument schema (typed: string, int, enum, target refs like tab/pane/workspace/group), target context kinds, availability predicate, default shortcut, cliName, menu placements.

Enforcement: a registry conformance test fails if an action lacks a cliName or a palette entry, if a context menu references an unknown ID, or if a handler is missing in the App. Adding a feature without all entrypoints does not compile/test. Layout/state mutations still go to the cmux-tui daemon, so the plain `cmux-tui` CLI can drive them even with the app closed; the app's action handlers are thin calls into daemon commands.

## Dogfood round 1 feedback (2026-09-29, nxdog2)

User: blurry tab titles; sidebar too heavy, remove workspace search; window drag needs its own state (workspaces + tabs to new window and back, empty-window handling); caret/focused-terminal desync; no Chromium option; weird keyboard interactions; omnibar must match Helium exactly; jank webview focus; split drags buggy (focus + blank panes); key priority tiers (Cmd-Option-Arrow etc. beat content); browser focus mode passes all keys except tier 0 to the page; each window owns its own state; state + concurrency audit, refactor implicit state machines.
Root-cause hypothesis (focus agent confirms in plans/cmux-next/focus.md): focus has no single owner; ~8 copies (AppKit responder, layout focusedPane, tab selection, sidebar selection, daemon defaults/optimistic patches, Ghostty focus, WebKit responder, CEF child window) synced by side effects with events arriving in different orders. Fix: per-window FocusCoordinator state machine (pure reducer + single idempotent effect applier), tiered key router, `debug.focus`; per-window WindowState + app-wide WindowRegistry for membership; terminal-keyed surface lifecycle with `debug.surfaces` invariants.
Agents: crisp, focus, window-drag, sidebar-min, omnibar, drag-panes, state-audit, roster-fence.
Empty-window handling, resolved (user 2026-09-30, "if no workspaces, by definition the window should not exist"): a window exists only while it holds at least one workspace; the "No workspaces in this window" state is deleted. `WindowRegistry` removes a window in the same transition that takes its last workspace (close, move by drag, CLI or palette, tear-off, removal by the daemon or another client), the only window too, and never registers a window without one. Each `DaemonStore` calls `onWorkspaceListChanged` synchronously after the batch that changed its workspace list, and `WindowManager.reconcileMembership` (the one pruning place) closes the window in that main-actor turn, at once (no fade: a fading window would show empty or fight the receiver for its surfaces). Focus goes to the window that received the workspaces, else the next window in z-order. Dragging (or "Move to New Window" on) every workspace of a window moves that window; no second window opens. New workspaces are claimed for their window before the create command, so a new window opens only in the step that first mirrors its workspace, and a window made for a workspace the daemon has not reported yet stays off screen until its content is installed. Closing the last window keeps the app running (`applicationShouldTerminateAfterLastWindowClosed` is false); the user-closed last window stays registered (closed) with its workspaces, a Dock click or Show cmux restores it, else Cmd-N, a Dock click, the menu and `cmux new-workspace` open a new window with a new workspace. Empty window records (older builds, other clients) are pruned in `WindowStateDocument.prune` and skipped by `WindowRegistry(records:)`; the daemon stores the projection opaquely and does not enforce it (cmux-tui-contract.md 2.6). The launch window shows the connecting state outside the registry until it receives workspaces. `debug.windows` reports membership and the invariants; `debug.focus` includes `window_invariants`. A window none of whose workspaces a machine reports (a saved window whose workspaces are gone or on a Cloud machine still connecting) stays off screen until one is mirrored, and the launch window adopts only a saved window it can fill. Tab drags follow the round 3 rule: a drag carrying every tab of its workspace moves the window when that workspace is the window's only one, else moves the workspace to a new window (tear-off) or to the sidebar slot (gap); dropped into another workspace, the tabs move and the emptied workspace closes (marked closing so the empty-workspace repair never refills it).

### Workspace verbs (user 2026-09-30, "think COMPREHENSIVELY"; feat-cmux-next-workspace-actions)

Each verb is one `ActionDescriptor` plus one handler (palette, CLI verb, editable shortcut, and the workspace row, sidebar background, group or pane context menu where it has a target). Sidebar order and groups are personal state (data-model.md 1.2c): every verb that changes order resolves a `WorkspaceSlot` against the window's sidebar and calls `SidebarBridge.place`, which writes personal order to the home session when it serves `profiles-v1`, else `move-workspace-to-group` on the owning daemon. A new workspace is placed once its daemon reports it (`WindowManager.pendingPlacements`).

Compared with Arc spaces (per-space folders, drag, "new tab here"), Chrome (duplicate, move to new window, close others/to the right, reopen closed), tmux/zellij sessions (new session in the current directory, `choose-tree` jumps, last-session toggle `prefix L`, move pane to a new session with `break-pane`, join with `join-pane`) and VS Code (duplicate workspace, reopen recent, sort, collapse all), a heavy user wants:

| Verb (action id) | Why |
| --- | --- |
| New Workspace Above / Below / at Top / at Bottom (`workspace.newAbove`, `.newBelow`, `.newAtTop`, `.newAtBottom`) | Arc "new tab here": the new workspace lands where the user looks, not at the end. |
| New Workspace in This Group / in New Group (`workspace.newInGroup`, `.newInNewGroup`) | Grouped projects grow in place; no create-then-drag. |
| New Workspace on Machine… (`workspace.newOnMachine`) | Sessions on several machines (data-model.md 1); pinned to the window's room so it shows. |
| New Workspace in Same Directory (`workspace.newInSameDirectory`) | tmux `new-session -c "#{pane_current_path}"`: a second workspace for the same repo. |
| Duplicate Workspace, with or without browser tabs (`workspace.duplicate`, `.duplicateTerminalsOnly`) | Chrome/VS Code duplicate: same screens, columns, splits, ratios and directories, new terminals (never a shared process), optionally the same pages. |
| Set / Clear Workspace Icon (`workspace.setIcon`, `.clearIcon`) | Arc space icons: an SF Symbol or one emoji tells workspaces apart faster than a color. |
| Move Workspace to Bottom, to New Group (`workspace.moveToBottom`, `.moveToNewGroup`); Move to Top now uses the same slot path | Completes Up/Down/Top; Move to Top used to write order to the workspace's own daemon in personal mode. |
| Merge Workspace into… (`workspace.mergeInto`) | tmux `join-pane` at workspace scale: every tab moves, the emptied workspace closes by the last-tab rule. |
| Move Pane to New Workspace (`pane.moveToNewWorkspace`) | tmux `break-pane`: a split that grew into its own task. |
| Close Other Workspaces in Group (`workspace.closeOthersInGroup`) | Chrome "close others", scoped to a project group; destructive, so it confirms. |
| Select First / Last Workspace, Switch to Last Used Workspace (`workspace.selectFirst`, `.selectLast`, `.selectLastUsed`, Ctrl-Cmd-`) | tmux `prefix L` / Alt-Tab between two workspaces is the most used jump; per-window recency. |
| Sort Workspaces by Name / Last Used / Directory (`workspace.sortByName`, `.sortByLastUsed`, `.sortByDirectory`) | VS Code/Finder sorting after a long day; each container sorts, groups keep their place. |
| Collapse / Expand All Groups (`workspaceGroup.collapseAll`, `.expandAll`) | VS Code "collapse all" for a long sidebar. |
| Copy Workspace Path (`workspace.copyPath`) | Paste the repo path into another tool; Reveal in Finder already existed. |
| Double-click empty sidebar space | Chrome tab strip / Finder: a double-click on empty space makes a new workspace there (end of the list, or end of the group under the pointer). |

Already present and kept: New Workspace, New Browser Workspace, Open Folder, Rename, Color, Description, Status, Move Up/Down, Move to Window / New Window, Move to Group / out of group, Move / Duplicate to Room, New Workspace in Room, Next / Previous (in group), Select 1…9, Close, Close Others / Above / Below, all group verbs, Reveal in Finder, Copy ID. Reopen Closed Workspace is ported: it reopens the newest workspace in the daemon's closed history (`closed.list`, `closed.reopen`) as a new workspace with its name, screens and tabs, and shows it in the active window. Terminals start fresh shells, since a workspace close ends them at once. Not restored yet (daemon side): the split layout (a screen's tabs land in one pane), the first terminal's directory, group, color, title, and the original window and position. Still typed unavailable, each needing daemon state: Pin Workspace (`workspace-pin-v1`), Mark Unread (`notification-mark-unread-v1`), Save as Template / New from Template (`layout-templates-v1`; `WorkspaceBlueprint` is the capture format it can store as personal state), Sort by Creation (no creation time on the wire). Proposed next: scoped jump (Go to Workspace in This Group / Machine / Room as a filtered palette page), Move Workspace to Machine (re-home, data-model.md 1.5).

Tab drag fixes in the same branch: a workspace moved by its last tab onto a sidebar gap, and a new workspace made by a tab dropped on a gap, both take the row-drag reorder path (the old path sent a sidebar index to the daemon's durable order and landed one slot off).

Shortcut editing in the palette: Cmd-K on a highlighted action opens an inline recorder (the Actions menu, Tab, lists Edit Keyboard Shortcut… too). A free chord saves at once to `shortcuts.bindings.<id>` (the settings watcher updates every window); a conflict shows the owner with Replace / Cancel and Keep Both only when every owner requires another context; a chord without Command or Control, a macOS chord, a tier 0 action's chord or a same-context numbered family is refused with the reason; a Chrome chord says who wins in a page (tiers 0 and 1 take it, a tier 2 action of another context leaves it); a Ghostty window/tab/split keybind is named (cmux runs first in a terminal). Delete removes, Shift-Delete restores the default (asking when another action took it), Escape cancels. Chords (two-stroke sequences) are not recorded, since the registry cannot dispatch them yet.
