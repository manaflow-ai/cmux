## What was checked for strict proof, and why the proven count is 0

Strict proof = sha, host, optimized build, bench and numbers beyond the noise band vs the base, for ONE mechanism; or a gate ON in CI or
the train that caught a named real defect; or a named user-visible bug fix with red/green. No row meets this today:

- Optimized builds that exist: only `chrome-parity-v2-2-3-opt` (job 5aad318613a5, commit 1b856ace18a). v2.2.4-opt (job 0fd2bb11383c)
  is still queued. No A/B of any single switch or mechanism has run on an optimized build (switch-table.md: 0 of 125 perf claims).
- Restore bench (restore-perf-result.md): v2.2.3-opt vs nightly-opt (job d55a43f7dac5, cc0d757) on cmux17/21/24, slowest visible pane live
  p50 373 vs 1018 ms at 60 workspaces warm, 230 vs 583 ms at 1 workspace. NOT proof of a row: it compares two whole builds (every
  dogfood switch at once), 2-3 runs, no noise band; it names no mechanism. It is the best lead for the restore and launch rows: an A/B per
  switch on v2.2.4-opt with the same bench turns it into proof.
- First-5s bench (first-seconds-lag-result.md, fixed sender): v2.2.3-opt meets 16.7 ms for split and address bar, but the base it compares
  with is v1.1 Debug; no optimized base and no per-mechanism A/B. The address-bar regression it found (breadcrumb scrub) is a felt-queue fix.
- terminalHolder key-to-frame (cmux21-perf, p95 4.2-4.5 vs 3.3 ms): v2.1 Debug. Debug does not count.
- Gates that caught real defects in the train (`train-red.jsonl`, `train.log`): `checks/shim-event-kinds.py` (missing CMUX_SHIM_LOCK and
  COLOR_CHOOSER cases, every Mac build of the tip red) and the generator/Cargo.lock checks are train tooling in /work, not program code.
  The crash ratchet refusal of p09-observability-101 (acpmux exit.waived 1 -> 2) used the waiver counter that was in the base before the
  programs (f071dffcd6b, 2026-10-23), and the waivers were later accepted after review, so it named no defect. No program guardrail

## Decisions applied (coordinator 2026-10-28 ~09:20Z, confirmed by cmux-ad)

1. **Host mode:** an A/B in the optimized bench build counts only if host mode's code also compiles and can run in Release
   (audit D2: behavior code compiles unconditionally) and the A/B shows a felt win beyond the noise band. Today host mode is
   `DEBUG || CMUX_BENCH_HOOKS` only, so every host-mode row is **unproven** and is removed on 11-04 unless D2 lands first.
2. **Gates:** only a recorded catch of a real defect by a gate that is ON in the train or CI counts; a replay is not proof.
   Gate rows whose check runs in the train (prepush-gate.py: guardrails, arch and crash ratchets, ast-grep; the compile-check)
   stay **planned** until 11-04: record each catch with its train number and the defect. Gate rows whose check is not in the
   train or CI (oracle, Debug-only checks, clippy, unit tests, not landed) are **unproven**.
3. **Owners:** every former "lead" row has a running owner role, marked "(proposed)" until the role accepts it by 11-01:
   p02/p06 sequence manager, p03 motion, p04 hold-class, p01/p05 daemon hot paths, p08 first-5s (pictures and restored pages:
   restore; PGO: fleet), p09 and the p12 canary fleet, other p12 landing, p14 memory/leaks, p15 spam. A row that no role
   accepts by 11-01 goes on the 11-04 removal list.
4. **Proof runs:** [proof-run-plan.md](proof-run-plan.md) groups the planned rows by bench and lists the A/B steps on the
   existing optimized build v2.2.3-opt (cmux-ad, 09:3xZ). Results are written here as strict proof rows.
