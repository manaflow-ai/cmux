# Plan tripwires

An opt-in plan build target starts one worktree child with instructions to write and declare real
tests first. The declaration tool belongs to the proven chat caller and is enabled only for that
child. The persisted manifest is bounded and cannot be replaced to discard an unresolved check.

Tripwires reuse the claim-checker's bounded observed runs and command classification. Turn-end
records and session summaries carry the same state; revision ordering prevents older transcript
pages from replacing the current header. Historical recaps retain their turn's evidence. A fresh
turn clears prior passing results. No new timer, observer, or transcript scan runs per token.

The UI reports evidence only. The existing stateless wrap-up tool cannot enforce completion, so
unresolved checks remain visible rather than claiming to prevent completion. A follow-up must
define a shared daemon completion contract before adding an enforcement promise.

See `design/tripwires.md` for the state transition and fixture detectors.
