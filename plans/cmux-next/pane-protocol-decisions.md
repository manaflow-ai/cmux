# Pane protocol decision log

The decisions and lane notes behind `pane-protocol.md`, in the order they were made (2026-10-04). Lane names (cmuxterm-hq-48 and others) are the session names of that day. This file replaces the scratch log `/tmp/pane-protocol/ir-changes.md`, which a temp cleanup deleted on 2026-10-05; the coordinator rebuilt it from the session transcripts. New decisions are added here, not in a scratch file.


## 2026-10-04 wire decisions from the TS lane (branch feat-cmux-next-pane-protocol-ts c48a9243e44); Rust and Go must match or object
1. `open` carries `id` and optional `params`; the peer answers with normal `ok`/`err`.
2. New message `{"t":"end","stream":<u32>,"code"?,"message"?}` ends or aborts a byte stream.
3. Stream ids by parity: the connecting side uses odd ids, the accepting side even ids.
4. Event `seq` starts at 1 per subscription.
5. Auth refusal: `{"t":"err","id":0,...}` before any other message. Optional auth ack `{"t":"ok","id":0}`.
6. Session-level error codes are `cmux.protocol.*` (`invalid_params`, `invalid_result`, `unknown_op`, ...).
7. With a schema, a session refuses ops/events not in the IR. Stream ops must therefore be declared in the IR.
8. MessagePort only: `{"t":"bye"}` before close.
9. Codegen refuses JSON Schema keywords it does not support (no silent accept-all validators).

## 2026-10-04 decisions after the Go lane (branch feat-cmux-next-pane-protocol-go a64ce096ba6), decided by cmuxterm-hq-48; Rust implements, objects here if needed
10. Capability token format: compact JWS, header {"alg":"EdDSA","typ":"cmux-cap+jwt"}, claims {sub, page?, app, ns[], scopes[], origin, aud, exp (Unix seconds), iat}. Base64url without padding.
11. Provider admission: `cmux.router.hello` params {proto, app, namespaces, ops, events, interfaces, ir, endpoints, credential?}; result {router_key (Ed25519 public key, base64url), provider (assigned id)}.
12. Request ids and stream ids are integers in 1..2^53-1 (JSON-safe in every language). A peer refuses larger ids with cmux.protocol.bad_message.
13. Added session-level codes: cmux.protocol.forbidden (scope or token does not allow the op), cmux.protocol.busy (provider overloaded, retryable), cmux.protocol.bad_message (malformed envelope or framing).
14. Third-party ops enter through their app manifest catalog fragment (JSON Schema), validated by the Rust fragment validator; the router's runtime registry = committed IR + installed fragments. A session's schema for a third-party namespace comes from the router (cmux.router.resolve returns the namespace's IR fragment digest; the client fetches it once).
15. Slow subscriber: a provider may drop events after a bounded queue; it must then send {"t":"ev","sub":N,"seq":S,"gap":true} for the first event after the drop, so clients know to resync instead of guessing from seq.

## 2026-10-04 coordinator decisions (REACT-PAGES Q7, R59)
16. One standard, secure custom scheme for every bundled page in both engines: cmux-page://<id>/ (the agent pane becomes cmux-page://cmux.agent/; cmux-agent:// goes away later). No loopback HTTP origin in acpmux. Pages' Origin is therefore cmux-page://<id>; listeners allow exactly the page origins their tokens name.
17. Keys: panes add no key handling; both engines feed the app's single key dispatcher.

## 2026-10-04 Rust lane (branch feat-cmux-next-pane-protocol-rust): what the Rust crate emits and enforces
Rust implements decisions 1-16. Points where Rust chose a concrete form, or differs:
R1. Unix framing: the 4-byte BE header's bit 31 marks a binary message (a data frame); the low 31 bits are the length (max 16 MiB). A text-only peer writes exactly the plain length prefix. Reason: binary frames on unix sockets need a type bit, and a reader that does not know the flag sees an oversized length and fails closed. Vectors: `unix_framing`.
R2. Token (decision 10): claims are {sub, page?, app, ns[], scopes[], origin?, aud, exp, iat}. `ns` is [] on page tokens; `origin` is omitted for native tokens. Header must be exactly {"alg":"EdDSA","typ":"cmux-cap+jwt"} (other headers: `wrong_header`). Origin rule: a connection WITH an Origin requires claims.origin == Origin exactly (normalized, `cmux-page://<id>` for bundled pages, decision 16); a connection WITHOUT one (native) skips the check. This matches the Go SDK. Go must add `page` and `iat` to its strict claims struct.
R3. Hello (decision 11): Rust takes the Go shape exactly: {proto:"cmux.pane/0", app, namespaces, ops:[{name,kind,scope}], events:[{name,scope}], interfaces:[string], ir:{version,sha256}, endpoints:[{kind:"ws"|"unix", url?|path?}], credential?}; welcome {router_key, provider}. `provider` is the app id, which is also the `aud` of tokens for it. `interfaces` apply to the provider's first namespace. First-party ops/events must match the IR's kind and scope.
R4. Ids (decision 12): call/sub/open/cancel ids, sub ids, seq and stream ids are 1..2^53-1; ok/err may carry id 0 (the auth reply only). Refusal code `cmux.protocol.bad_message`; the reply echoes the id when it can be read.
R5. Auth refusal (decision 5): err id 0 with code `cmux.protocol.auth_refused` and details.reason (timeout|closed|missing_token|invalid_token), then WebSocket close 4001. Success: ok id 0 with value {sub, app|page, exp, provider}. Mid-session expiry: `cmux.protocol.token_expired` (retryable).
R6. Codes Rust sends: closed, cancelled, unknown_op, unknown_stream, invalid_params, invalid_result, internal, stream_aborted (wrong-parity or reused stream id), credit_exceeded, auth_refused, token_expired, forbidden, bad_message, busy, not_routed (router asked to carry a data-plane op), too_large. Op codes: cmux.git.not_a_repo, cmux.git.bad_ref, cmux.router.refused, cmux.router.no_provider.
R7. Gap (decision 15): `seq` counts events actually sent (contiguous); `gap:true` marks the first one after a drop. Omitted when false.
R8. `open` of an op with no stream handler answers `cmux.protocol.unknown_op`; Rust declares no stream ops yet (OpKind has `stream`).
R9. IR shape changes vs the seed: every op has `owner` ("first-party" | "app:<id>") and optional `aliases`; op `kind` may be `stream`; interfaces[] use the cmux-app-host shape {name, version, docs, props, methods{name: signature}, events[], status} (no `ops` key); types carry schemars output: descriptions from doc comments, `format` (uint64/uint32) and `minimum: 0` on unsigned ints, `default` on defaulted fields, `oneOf` + `const` for the tagged PageProvider. All inside the decision-9 subset (checked by a test). Every object's keys are sorted.
R10. IR content added: cmux.router.{hello, resolve, token.refresh, interfaces.list, pages.list}, event com.example.hello.greet.ticks (seq vectors), types ProviderHello, ProviderWelcome, HelloOpRef, HelloEventRef, HelloIr, Endpoint, EndpointKind, ResolveParams/Result (with `ir` digest, decision 14), TokenRefreshParams/Result, InterfacesList*, InterfaceListing, ProviderInfo, PageManifest, PageProvider, PageEngine, PagesList*.
R11. Third-party app ids/namespaces are <publisher>.<name> with labels [a-z0-9_] ('-' -> '_'); `com.example.hello` stays valid. Vectors that the TS/Go harnesses do not consume sit outside `vectors[]`: transport_envelopes (auth, bye), unix_framing, token, session, fragments, ir_keywords.

## 2026-10-04 Go lane after the Rust vectors (branch feat-cmux-next-pane-protocol-go)
Go now passes every Go-relevant section of vectors.json: vectors[] (with canonical re-encoding), unix_framing, transport_envelopes, token (the vector key re-mints the vector token byte for byte), session (played against the Go example provider), plus fragments and ir_keywords in the Python generator tests. Go implements decisions 1-17 and R1-R11. Notes and objections:
G1. Objection (aliases, decision 14): the valid fragment vector aliases `octo.diff_tools.diff.list` as `difftools.list`, which is outside the app's namespace. Free-form aliases let a third party claim names that nobody reserved. Go accepts that vector, but it refuses (a) an alias inside a namespace of another owner, and (b) any third-party alias equal to `cmux` or starting with `cmux.`. Without (b), an app can squat a first-party name that has not shipped yet (`cmux.git.blame`). Please add both rules to the Rust fragment validator and add a vector for each. Better still, confine third-party aliases to the app's own namespace, or drop them.
G2. `pattern` (decision 9): Go validates with RE2 and refuses lookaround and backreferences when it generates the package. TS uses ECMA-262. Please limit `pattern` in the subset to RE2 syntax and have the fragment validator refuse the rest, or the languages will disagree.
G3. `allOf`: Go supports only a single-schema `allOf`. A multi-schema `allOf` is refused at generation. The Rust IR has none today.
G4. WebSocket without an Origin header: Go refuses it with 403, and native peers use the unix socket. R2 lets an Origin-less connection skip the check. Go applies that rule only to unix peers. This does not weaken security, because a native process can forge Origin anyway.
G5. bad_message replies echo the id when it is readable and in 1..2^53-1. Otherwise they use id 0. After auth, a TS client must not read an err with id 0 as an auth refusal (TS checks this only before auth today, which is correct).
G6. HelloIr.sha256 is the SHA-256 of the IR file bytes. For a third-party provider, it is the SHA-256 of its fragment file bytes (the value that cmux.router.resolve returns as `ir`).

## 2026-10-04 decision 20 (coordinator, implemented in Rust): workspace roots
20. Capability tokens gain a `roots` claim: an array of absolute canonical directory paths (the page's workspace roots). Every op param that names a filesystem path (cwd, path) is canonicalized by the provider (resolving `..` and symlinks) and refused with `cmux.protocol.forbidden` unless the result is inside one root (component-wise prefix, so `/a/rootx` is not inside `/a/root`). An empty or missing `roots` allows no path-taking op. The provider passes the canonical path on to the handler. The router canonicalizes roots when it mints and copies the page token's roots into the data-plane tokens from resolve.
- What changes for TS and Go: only the claim shape. Claims are now {sub, page?, app, ns[], scopes[], roots?[], origin?, aud, exp, iat}; `roots` is omitted when empty. Go's strict claims struct must accept `roots` (and `page`, `iat`). The token vector's claims now carry `roots: ["/home/user/repo"]`.
- Vectors: `roots` (a directory layout with symlinks, built under a temp dir as `$BASE`, then 11 allowed/refused cases: inside, the root, a symlink that stays inside, `..` that stays inside, outside, a symlink that escapes, `..` traversal out, a prefix-sharing sibling, a relative path, a missing path, a missing roots claim).
- Also from the same request: a FIRST-PARTY hello whose `ir.sha256` differs from the router's IR digest is refused with `cmux.protocol.bad_message`, details.reason `ir_mismatch`; a third party's digest is recorded and allowed. Vectors: `admission` (3 cases, with `router_ir_sha256`).
- Rust only (no wire change): accept loops back off 10 ms doubling to 1 s, reset on success, and log once per burst.

## 2026-10-04 decision 21 (coordinator request for the codemode lead, R73, plans/cmux-next/app-commands-codemode.md)
Per op in the IR:
- `scope` (required, explicit; already planned).
- `mcp`: `{"expose": "default" | "opt_in" | "never", "group"?: string}`. An op without `mcp` is `{"expose":"never"}` (fail closed). Third-party fragments carry it as declared; the merged registry refuses two ops with the same MCP tool name (op name with `.` and `-` as `_`, max 48 chars).

Optional: an op without `cli` has no CLI verb. The app-level `cli.name` lives in the manifest, not in the op.
- `x-cmux-secret: true` is an allowed JSON Schema extension keyword on a property in a result or event schema (in every generator's keyword subset). emit-ir derives `secret_output: boolean` per op: true when any property reachable from the result schema has `x-cmux-secret: true`. Consumers must use `secret_output`, not re-walk schemas. Ops with `secret_output: true` are never offered to agents (agent_view excludes them).
Vectors: one valid op with all fields; mcp.expose outside the enum (invalid); a bad cli.path (invalid); two ops with the same MCP tool name (invalid merge); a result with a nested x-cmux-secret property gives secret_output true; an op without mcp gives expose never.

## 2026-10-04 decisions 24-26 by cmuxterm-hq-48 (after the Go lane's roots work)
24. A call without a token (the router's own connection to a provider) has no roots, so every op with `paths` is refused there (fail closed). The router never calls path ops on behalf of pages; pages call providers directly.

The two "same MCP tool name" fragment vectors must use valid three-part names, so they test the tool-name rule and nothing else.

## 2026-10-04 decisions 29-30 by cmuxterm-hq-48 (Go lane questions after decision 27)
29. Gesture proof travels in the call envelope: `{"t":"call", ..., "gesture": "<compact JWS>"}`. The host (engine bridge) mints it for a real user event only, as the app ABI's gesture rules say: typ `cmux-gesture+jwt`, claims {sub (page instance), app, aud (provider), op (the op name it may be spent on, or "*view" for any view-state op), exp (10 s), jti}. A provider refuses an op with `gesture: true` when the call has no valid gesture token for that op and audience: `cmux.protocol.forbidden`, details.reason `gesture_required`. Each jti is spent once per provider (keep a bounded set until exp). Rust implements the minting and verification types in the crate; Go and TS implement verification and carrying.
30. `server_only`: defense in depth. The router never puts a server-only scope into a page or data token minted for a page, and a provider refuses a server-only op when the token has a `page` claim (`cmux.protocol.forbidden`, reason `server_only`). Both are enforced.
Scope collision question: decided as decision 28 (third-party scopes are `<own namespace>:<verb>`).

## 2026-10-04 decision 29 amendments (Go lane questions)
29a. Key: the ROUTER signs gesture tokens with its existing Ed25519 key; providers verify with the router_key from the admission welcome (no second key). The engine bridge asks for one through a new control op `cmux.router.gesture.mint {page, op}` on its host connection, only while it handles a real user event; the op is server_only (pages can never call it), risk mutate-own, gesture false.
29b. ## 2026-10-04 decision 31 by the zero-latency lane (hq48-zero-latency)
31. Operation ids. `call` may carry `"opid":"<string>"` (1 to 128 characters of `[A-Za-z0-9._:-]`), a client-generated operation id for one user intent. A provider that applies the call echoes the id on every event the call caused: `{"t":"ev","sub":…,"seq":…,"data":…,"opid":"<id>"}` (envelope field, outside the IR-validated `data`). A provider applies an opid once per caller identity (the token's `sub`, the page instance, so a resend on a new connection after a reconnect is covered): a repeated opid is answered with the first run's `ok` or `err` and runs nothing. Remember at least the last 1024 opids per caller for 10 minutes. `ok` and `err` are matched by `id` and carry no opid. A malformed opid is a bad message (`cmux.protocol.bad_message`). TS: `CallOptions.opid`, `HandlerContext.opid`, `emit(data, {opid})`, `onEvent(data, seq, {opid})`, `OpidLedger` for providers, and the page bridge carries it (`PageClient.call(op, params, {opid})`). Rust and Go providers follow; no Rust change in this slot. Design and rules: plans/cmux-next/zero-latency.md.
