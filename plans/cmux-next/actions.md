# Action surfaces

User rule (2026-10-01): every action is supported from the CLI, a right-click menu and the command palette where that makes sense, and this is checked mechanically.

## Data structure

Each `ActionDescriptor` carries `surfacePlan: ActionSurfacePlan` (`Sources/CmuxNextActions/ActionSurfacePlan.swift`):

| Surface | Declaration | Generated where |
| --- | --- | --- |
| Palette | `palette: SurfaceDecision` (offered, or `paletteInternal` for actions that require the palette open) | `RegistryPaletteProvider` lists `isPaletteVisible` |
| CLI | `cli: SurfaceDecision` (offered = the `cmux <noun> <verb>` verb `cliName`; exempt = only `cmux action run <id>`) | `action.list` `surfaces.cli`; the Rust CLI routes offered verbs to the app |
| Right-click | `contextMenus: [ContextMenuPlacement]` (menu, `MenuGroup`, rank, style item/choices/submenu, parent, `MenuFolder`) or `contextMenuExemption` | `ContextMenuCatalog` builds every menu from placements: groups in `MenuGroup` order, separators between groups and between rank hundreds; rows with a folder go into a titled submenu (New, Split, Agent, Open In, Appearance, Options, Group, Move, Layout, Connection, Copy, Tools, Close) after their group's rows, and a folder with one row shows it inline. Each menu keeps at most 12 top-level rows (Lawrence, 2026-10-01) |
| MCP | follows the CLI; `mcpExemption` (credentials, endsApp, systemChange) removes a verb from `cmux mcp serve` | `action.list` `surfaces.mcp` |
| Keyboard | every action binds by `id` (`cmux.json` `shortcuts.<id>`, Settings shortcut editor lists the registry); defaults stay optional | `ActionRegistry` shortcut index |
| Main menu | optional `mainMenu` (not every action belongs in the menu bar) | `makeMainMenuItems` |

Every exemption names a `SurfaceExemption` reason. A descriptor may declare `surfacePlan:` inline; otherwise `ActionSurfaceCatalog` (`ActionSurfaceCatalog+Menus.swift`, `ActionSurfaceCatalog+Exemptions.swift`) fills it after the domain catalogs build, keyed by action id. Every surface calls `ActionRegistry.perform` with the caller's origin: menus and palette `user`, the control socket the request's `origin` (`cli`, `script`, `mcp`).

## Verification

`scripts/cmux-next/check-action-surfaces.sh` (about 30 s once built) runs `ActionSurfaceParityTests`, `ActionContractTests` and `CLISurfaceParityTests`. Over the whole finite catalog they check: every surface declared; placements and exemptions consistent (no placed-and-exempt, `devOnly` only on debug-only actions, MCP exemptions only on CLI verbs, choices only with menu choices, submenu parents exist); each target kind's menu shows every action on that kind (directly, through containment: a tab menu reaches its pane, or in an object-less menu); each generated menu shows exactly its placements (inside submenus too) and keeps at most 12 top-level rows, every folder holding two or more; unique CLI names and default shortcuts; every menu item runs its own action through the registry with the item's target and the user origin; every CLI verb runs its own handler by CLI name with the caller's origin; `action.list` reports every surface; `plans/cmux-next/action-surfaces.json` (the export the Rust CLI and MCP parity tests read) and the generated block below (counts, every menu in order, every exemption) are fresh; every table id names a catalog action. Rewrite the export with `CMUX_UPDATE_ACTION_SURFACES=1 swift test --filter ActionSurfaceParityTests`.

`action-surfaces.json` is the one catalog other clients (the Rust CLI, MCP, cmux-browser, GPUI) read. Each action row has: `id`, `cli_name`, the surface fields (`palette`, `cli`, `context_menu`, `context_menus`, `mcp`), `title` (English), `title_key` and `title_table` (the localization key and its `.xcstrings` table in CmuxNextActions; null when the key cannot be named: the key is `action.<id>` by convention, else the one string whose English text is the title), `default_shortcut` (`{"key": "i", "modifiers": ["cmd"]}`, modifiers in the order ctrl, opt, shift, cmd, `"family": "digits"` for a 1 to 9 family; null when none) `default_chord` (two such objects, the leader layer; null when none), `default_aliases` (the binding table's extra default keys for the action, `KeyBindingDefaults`: `[{"keys": [shortcut...], "when": "<when clause>" or null}]`, empty when none) and `palette_section` (`id`, `title_key`, `title_table`, English `title` and `order`: the command palette section the action lists under, from its category). All fields are generated; `exportIsFresh` fails on any changed title, key or shortcut until the export is rewritten.

## Known hand-composed menus

These menus still compose or filter generated entries at the call site; each filter uses state the catalog cannot see. The tab menu hides the engine a browser tab is on, terminal themes and keep-running on pages, and hibernation on terminals (`PaneController+Intents.swift`). The empty tab strip shows the new-tab menu followed by the pane menu. The notifications panel builds its rows from the `.notification` placements and hides Toggle Read on a read row. The workspace row menu hides Dismiss Highlight while the workspace draws no attention ring (`SidebarContextMenus`). `BrowserProfileLinkMenu` inserts the browser profiles for a hovered link into the terminal and page menus (`openLinkInDefaultBrowser` and `browserProfile.openLink` stay `noTargetSurface`). A page right-click starts with the `browserLink`, `browserImage` and `browserSelection` menus for what it hit (`BrowserHitMenu`, the same rows in WebKit and Chromium); their rows run with the hit's `url` and `text` as arguments (`makeContextMenu(arguments:)`), Copy Link Text hides when the link's text is unknown, and Search and Look Up show the selected text in their titles.

## Adding an action

Declare its placements (menu, group, rank) and whether the CLI offers it, or name the exemption. `check-action-surfaces.sh` fails until you do.
