# Brief for cmux-next feature agents

- Read plans/cmux-next/REWRITE.md (goals, visual rules, decisions), plans/cmux-next/architecture.md (binding: state ownership, AppKit-first, RAM/CPU budgets), and the design doc named in your task.
- Setup: `git -C /Users/lawrence/fun/cmuxterm-hq/worktrees/feat-cmux-next worktree add /Users/lawrence/fun/cmuxterm-hq/worktrees/feat-cmux-next-<slug> -b feat-cmux-next-<slug> origin/feat-cmux-next` (fetch first). Work only there. Never edit the feat-cmux-next worktree itself.
- Own only your module under Packages/macOS/CmuxNext/Sources/<Module> and its Tests dir. Do not edit Package.swift unless you must add a dependency to your own target (say so in your reply). Do not edit other modules; if you need something from another module, define a small protocol in your own module.
- Feature UI modules never import CmuxNextDaemon. Expose an @Observable @MainActor view-model / input protocol that the App layer will fill from daemon state. Include a mock data source so the module can be demoed alone.
- Write NEW code. Do not copy old cmux Swift. Modern Swift 6, AppKit-first for performance-critical chrome, SwiftUI inside NSHostingView where apt, Observation, no DispatchQueue.asyncAfter, no sleeps for synchronization. User-facing strings: String(localized:defaultValue:bundle: .module), add keys to a Localizable.xcstrings in your module with en + ja.
- Visual: NO blue accents. Subtle grays for selection/hover/focus. Liquid Glass (NSGlassEffectView / .glassEffect via CmuxNextDesign helpers) where it reads clean, never behind terminal text. Chrome/Arc/Raycast-grade polish, 120 Hz-smooth animations, respect Reduce Motion.
- Verify: `swift build --build-tests` in Packages/macOS/CmuxNext. Pure-logic tests with Swift Testing; `swift test --filter <Module>Tests` is allowed for this package (it does not launch cmux DEV). Never run xcodebuild test. For a visual check, a tiny throwaway demo executable in /tmp that links your module is fine; screenshot it with cmux-cua MCP tools in background mode; never touch the user's cmux windows; kill what you launch.
- Commit on your branch (messages end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`), push the branch, open a PR into base `feat-cmux-next` on manaflow-ai/cmux (body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`). Never push main.
- Run long builds blocking in the foreground. Final reply: public API of your module (types + key methods), what is verified, what is not, PR URL, decisions you made that the user should know.
- Merge gate for every PR into feat-cmux-next: `scripts/cmux-next/check-no-godfiles.sh` and (once it exists) `scripts/cmux-next/check-concurrency.sh` pass. Follow architecture.md section 5a: never block the main thread, every cross-process call async with a deadline, read-only control methods answer off-main from ControlSnapshot, mutations through the bounded MainActorWorkQueue.
- Launch tagged builds with a clean environment (`env -i HOME=$HOME USER=$USER PATH=/usr/bin:/bin`), `CMUX_NEXT_NO_ACTIVATE=1` and `CMUX_NEXT_SOCKET_MODE=automation`. No ad hoc Accessibility/AppleScript window moves; if a path cannot be verified, report it UNVERIFIED.
- Tagged builds are stock: fleet `~/.local/bin/cmux-ci build cmux --ref <sha> --tag <tag>-v1 --workspace <PR URL> --receipt artifacts/fleet/<sha>-submit.json` then `cmux-ci wait <id>` (on timeout wait again, never resubmit, never pass `--min-free-bytes`), or local `./scripts/reload.sh --tag <tag>`. Both fetch the cmux-tui pinned in `scripts/cmux-next/cmux-tui.pin` from its public files.cmux.com URL (sha256-verified, no GitHub login) and fail if the bundle carries anything else; check `Contents/Resources/bin/cmux-tui.version`. Never set `CMUX_TUI_CLIENT_MAX_FALLBACK` or swap binaries into a built app; bundle a local cmux-tui with `CMUX_NEXT_TUI_BIN=<path>`. Refresh the pin as `scripts/cmux-next/pin-cmux-tui.sh --help` describes. Fleet builds have no CEF (the private manaflow-ai/cef release needs a GitHub token the workers lack), so the browser reports the Chromium engine unavailable there.
- Local cmux-next reloads need `CMUX_NEXT_MIN_FREE_GIB` (default 40) GiB free and then lift the local build guard's 500 GiB floor for that build only; do not set `CMUX_ALLOW_LOW_SPACE_BUILD=1` yourself.
- Visual evidence without moving windows or taking focus: add `CMUX_NEXT_TEST_WINDOW_SCREEN=last` (or a `NSScreen.screens` index; 0 is the menu-bar screen) and optionally `CMUX_NEXT_TEST_WINDOW_FRAME=x,y,w,h` (points, from the top-left of that screen's visible frame; default 1100x720 centered) to the no-activate launch. Only with `CMUX_NEXT_NO_ACTIVATE=1`, the app places its own windows there and orders them front with `orderFrontRegardless`; it never activates and no window becomes key. `last` is the agent default: a secondary display when one exists, else the only screen. Capture only the tagged window: `screencapture -x -o -l <CGWindowID> out.png` (find the id with cmux-cua `list_windows` filtered by the app's pid).
