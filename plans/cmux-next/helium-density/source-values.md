- The horizontal tab strip region is **re-parented into the toolbar**. It goes after the location bar with flex order 1004, it can shrink to zero, and it is masked to bounds. There is no separate tab-strip row. ([HP/layout/compact.patch#L55-58](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/compact.patch#L55), [L67-91](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/compact.patch#L67), [L177-208](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/compact.patch#L177))
- The location bar has a **fixed preferred width of 350** and height 28. It has only a leading margin (6) and is never centred. ([compact.patch#L141](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/compact.patch#L141), [L217-218](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/compact.patch#L217), [toolbar-layout.patch#L176-183](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/toolbar-layout.patch#L176))
- The toolbar becomes the top-most row and enters the caption-button (traffic-light) exclusion with `kTopToolbarExclusion = 10`. ([toolbar-layout.patch#L17](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/toolbar-layout.patch#L17), [L59-67](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/toolbar-layout.patch#L59))
- The new tab button is hidden when the strip region is narrower than 28 + 3. ([compact.patch#L309-319](https://github.com/imputnet/helium/blob/a2d96a753a3e9f10e10170615f8eaed6b159e85b/patches/helium/ui/layout/compact.patch#L309))
- All layout constants (tab, close, toolbar, omnibox) are the same as in classic. Compact changes only the arrangement.

## UNVERIFIED

1. **`kCloseWeight500CustomIcon` and `kAddWeight500CustomIcon` glyph geometry** (Helium's close and + glyphs, because `kRoundedIcons` is ON). The `.icon` files are not in the public Chromium tree at 157.0.8103.78: `git ls-tree` finds no `*weight_500_custom*`. They are generated or vendored elsewhere, so the stroke width and extents are unknown. Only the box sizes (14 and 16) are verified.
2. **Composited hex values for alpha colors** are approximations (Chrome SysSurface4 ≈ #EDF2FA; Helium omnibox ≈ #EDEDED on white). I computed them by hand from AlphaBlend/SetAlpha. I did not render them.
3. **Chrome's stock colors assume the baseline palette** (no user color, no accent, no custom theme, `kChromeDarkNeutrals26` OFF). A Chrome profile with "Device colors" or a user color uses generated tonal palettes ([ref_color_mixer.cc#L256-290](https://github.com/chromium/chromium/blob/157.0.8103.78/ui/color/ref_color_mixer.cc#L256)). I did not check which branch a fresh macOS Chrome profile takes.
4. **Finch / field trials**: all feature states are source defaults. Google can change stock Chrome on the server side (for example `kTabStripDeclutter`, `kRoundedIcons`, `kOmniboxResizingPrioritization`, `AdjustOmniboxIndent` params). I did not read the defaults of the `omnibox_feature_configs::AdjustOmniboxIndent` offsets.
5. **Omnibox 14 pt fitting in Helium's 24-px text height**: this is derived from `DeriveWithHeightUpperBound` with typical SF Pro 14 pt metrics (cap height about 10, line height about 17). Real font metrics were not measured.
6. **Compact layout vertical geometry**: the tab strip region (preferred height 34) sits in a toolbar with 28 px of content height. How FlexLayout clamps it, and whether tabs drop below `kTabHeight` (31), which would hide icons ([tab.cc#L1311](https://github.com/chromium/chromium/blob/157.0.8103.78/chrome/browser/ui/views/tabs/tab.cc#L1311)), was not traced.
7. **Gap between extension action buttons**: each item has VH(0,2) margins, but I did not confirm whether the animating FlexLayout collapses them (2 px) or adds them (4 px).
8. **Tab strip leading inset next to the traffic lights** (`GetHorizontalTabStripLeadingMargin`, and the 12-px mac internal padding that applies only with leading buttons, [horizontal_tab_strip_region_view.cc#L72-73](https://github.com/chromium/chromium/blob/157.0.8103.78/chrome/browser/ui/views/frame/horizontal_tab_strip_region_view.cc#L72)): not traced for either browser.
9. **Helium `remove-toolbar-corners.patch`, `rounded-frame-corners.patch`, `frame-background.patch`, `helium-noise-page-info.patch`**: I did not tabulate these. They can change the toolbar/frame edge treatment and the page-info chip look.
10. **CONTEXT_TOOLBAR_BUTTON label point size**: it depends on font-height fitting in 17 px, so it was not resolved to a point value.
11. **Chrome new tab button background hex** (§8): the mixer maps it to `kColorSysHeaderContainer` ([material_tab_strip_color_mixer.cc#L87-90](https://github.com/chromium/chromium/blob/157.0.8103.78/chrome/browser/ui/color/material_tab_strip_color_mixer.cc#L87)). The values Primary95 #ECF3FE (light) and Neutral25 (dark) for SysHeaderContainer were not read from sys_color_mixer.cc. Also, the content-area separator row in §8 was not re-checked line by line.
