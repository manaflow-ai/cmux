# Lane: dialogs

## Active streams
- R96 custom dialogs lead: every dialog is a cmux dialog, no system alerts or panels (Lawrence 2026-10-04; supersedes "quit = plain NSAlert"). ONE mechanism: `CmuxDialogCenter.shared.present(spec, in: .tab(view) | .window(window) | .app)` in CmuxNextDesign/Dialog, drawn on the R84 `WindowOverlayHost` (above every Chromium page). Clicks, keys (`CmuxDialogKeys`: Return default, Escape cancel, Command+key, Tab trapped) and automation (`debug.dialog`) take the same path; one answer per dialog; `answer.isDismissal` when nobody pressed a button. Open: CEF JS dialog/file/auth/permission/download handlers (browser lead, after R84, call this API); open/save panels move to the R89 picker (hq-48, with a save mode); cmux explainers before macOS-drawn prompts (D4) and before protected folders with a Full Disk Access offer (D2).

- Toasts (R96, owned by the dialogs lead): ONE presenter `CmuxToastCenter.shared.show(CmuxToast(id:message:action:duration:), in: window) -> CmuxToastHandle` (onAction, onDismiss(reason)) on the R84 overlay `.toast` kind; at most 3 per window, newest at the bottom, same id replaces; auto-dismiss on an injected clock (DemandTimer), held while hovered; VoiceOver announcement; Cmd-Z runs the newest undo toast only when the first responder's undo manager cannot undo, through the key dispatcher hook `takesUndoKey(in:)` + `runUndo(in:)` (keybindings lead wires it). Clients: R134 hide-app undo, R93 customization undo, the Reopen-closed toast.

- R96 quit hook ids and restore base (R96 v2, for hq-48 file pages): ONE id format for a quit participant and its recovery draft, `file:<host id>:<canonical path>` (host id "local" for this Mac; `QuitParticipantID.file(host:path:)`, `.parse`). `QuitUnsavedRegistry.register` refuses any other id (logged by shape, never the path or contents; the registration is inactive, `isActive` false). `RecoveryDraftStore.update(id:title:contents:host:filePath:base:)` refuses a malformed id or a host/path that disagrees with the id (`.invalidID`); `host` nil = the id's host. `base: RecoveryDraftBase(modified:size:contentHash:)` is the file state the edits came from (contentHash = lowercase hex SHA-256 of the bytes; it alone decides when present); the launch toast compares the file with the base, so an outside change during the 1 s debounce is flagged. No base = old behavior (date and size at the delayed write). A draft of another host is never compared with a local file.
