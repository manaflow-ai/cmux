Leo, 2026-11-24, ask (a): "make dying agents with important work more persistent".

## Cause

3 of the 11 dead sessions on NOW died after a daemon restart. The restart path already does what the ask wants. `restart_resume.rs` queues a one-time continuation of the cut turn ("acpmux restarted ... while your previous turn was running"), bounded by `autoResumeDelaysMs`. That continuation was queued and then started. The 2026-10-22 rule ("goes on by itself") held.

It was refused anyway. The logs of two of them (a Mac host's mac-runners-heal-origin, seq 177–183, and cmux24-runner-heal, seq 166–172) both read:

`auto_resume_scheduled` → `queued ~resume-1` → `turn_result failed outcome_unknown` → `queue_removed` → `prompt_refused session.folder_missing`.

These were proven-peer chats that named no folder. Their folder was `<temp>/acpmux-peer-scratch-<uid>-<id>/<name>` (`server/remote_guard.rs` `peer_scratch`). On macOS that is under `/var/folders/.../T`, and it did not outlive the restart. So the continuation had nowhere to run, and the chat sat idle with its turn marked failed.

## Fix

`folder_ready`, the check before a cold prompt, now makes a missing peer scratch folder again. It does this before it refuses the prompt (`hub/worktree_care/scratch.rs`). The folder is made at the same path, owner-only, with the acpmux marker. The agent's own history (Claude Code keys it by folder) then resumes there, and the queued restart continuation runs.

Limits on what it will make:
- Only that exact shape: `acpmux-peer-scratch-<this uid>-<32 hex>/<scratch_name leaf>`.
- Only in this user's temp dir.
- A root or leaf that already exists must be this user's own 0700 directory, never a link. Anything else is left alone and refused as before.

Nothing else changes. No default changed: the existing recovery path, its once-per-turn bound and its off switch are untouched. The scratch folder never held the person's files.
