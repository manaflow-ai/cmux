RFD 0007 (projected folders), seed bundles: "Yes, a repo with a public remote should still take its objects from the remote (C): 0.27 GB instead of 45 GB over the Mac's link for this folder's repos. The open part is the swap: serving `.git` by projection until the machine's own fetch lands, then switching to it."

## What changes
- A projected repository with a public remote gets its own repository on the machine. The machine does a blobless fetch from the remote, then takes only the Mac's unpushed objects over the link, along with its refs, index, HEAD and config.
- `.git` is served by projection until that repository is ready. Then it switches from projection to a link to that repository, in one `renameat2` in the upper layer, under a new inode number. A git process that already holds the old `.git` keeps reading the manifest's tree.
- Reads of a lower `.git/objects/pack/*.pack` that aren't cached now fetch and cache 128 KiB blocks. Before, each touch fetched a 4 MiB chunk, so fetching the Mac's unpushed objects pulled in most of the pack.
- The machine repository's git commands take `GIT_DIR` from the environment, not `--git-dir`. A git wrapper on PATH that reads only the command line had turned the seed fetch into a silent no-op.
- The machine turns this on with `CMUX_PROJECTION_GIT_SWAP=1`. Nothing changes by default.

## Number
Bytes over the Mac link for one repository's `.git` (42 MB pack; the workload is `git log -p --all` plus `git status`; harness is `git_swap::tests::bytes_over_the_mac_link_before_and_after_the_swap`):
- projection only: 50,368,207 bytes
- fetch plus swap: 429,745 bytes

## Tests
`cmux-tui/crates/cmux-projection/src/git_swap_tests.rs` covers the swap, unpushed commits surviving it, a git process reading during the switch, and the byte count above.
