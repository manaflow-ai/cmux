# cmux-next third-party notices

`THIRD_PARTY_LICENSES.md` at the repository root is generated by
`scripts/cmux-next/generate-third-party-notices.sh` (`--check` fails when it is
stale). Do not edit it by hand.

- `hand-written.md` holds the sections that no tool generates yet (Ghostty,
  Sparkle, Swift packages, web assets, encoders and others). It is owned by the
  license review: change it only with a license-review reason, and never edit a
  license text. The generator copies it byte for byte and adds a
  `<!-- notices-section: manual-<heading> -->` marker before each `## ` heading.
- The Rust sections come from `cmux-tui/build-support/notices/rust_notices.py`
  (shared with cmux-browser). License-review data for them is in
  `cmux-tui/build-support/notices/reviewed.json`; `REVIEW.md` there lists every
  choice with its source and sha256.
- `bundle-map.json` maps every Mach-O file of the app bundle to the notices it
  needs. `scripts/verify-app-bundle-licenses.sh` runs `check_bundle_notices.py`
  and fails on an unmapped binary or a missing notice. Add a map entry in the
  same change that adds a binary to the bundle.

section), CEF's own LICENSE.txt in the framework, release-time regeneration in
