# cmux tree

`cmux-tree` は複数のマシンで動く Codex を監視する読み取り専用 TUI です。3 列にマシン、サブエージェントを含む Codex の会話、選択した会話の軌跡を表示します。

バイナリ名は `cmux-tree` です。既存の `cmux tree` コマンドは Swift アプリのペイン階層を表示するため、この初期版では置き換えません。

## 実行

リポジトリでビルドして起動します。

```bash
cd cmux-tui
cargo build -p cmux-tree
target/debug/cmux-tree
```

標準の設定ファイルは `~/.config/cmux-tree/config.json` です。別のファイルを使う場合は `CMUX_TREE_CONFIG` または `--config PATH` を指定します。

## Rust フックから Codex を起動

`cmux-tree-hook` は Rust で書かれた Codex 互換ランチャーです。通常の対話起動または `resume` では、Codex の標準 Unix socket を確認します。socket がない場合は、公式の `codex app-server daemon start` コマンドを実行します。このコマンドはサーバーの準備完了後に戻ります。その後、フック自身のプロセスを実際の Codex バイナリに置き換え、すべての引数と最終的な終了ステータスを維持します。

```bash
target/debug/cmux-tree-hook
target/debug/cmux-tree-hook resume --last
```

フックは最初に `CODEX_HOME` 内の managed standalone バイナリを探し、次に `PATH` 上の `codex` を探します。特定の実行ファイルを使う場合は `CMUX_TREE_CODEX_PATH` を設定します。

Codex は完全な対話型チャットクライアントのままです。現在の Codex は、実行中の管理デーモンへ対応する対話起動を自動接続します。`cmux-tree` は同じデーモンへ 2 本目の接続を開き、同じ会話を監視します。Codex バイナリの解決後、デーモン実行中の経路は socket 情報の確認 1 回だけを行い、サブプロセスを起動しません。フックはプロセス置換を使うため、ヘルパーはメモリに残りません。ライフサイクルフックをインストールせず、ターン、ツール、停止イベントごとのプロセスも起動しません。

`exec`、明示的なリモート接続、プロファイル、コマンドライン設定の上書き、フック機能の上書き、strict config では Codex の埋め込みサーバー動作を維持します。Rust フックは、これらの起動では使われないローカルデーモンを開始しません。デーモン起動に失敗した場合も通常の Codex 起動へ進み、Codex 標準の埋め込みサーバーへのフォールバックを維持します。

この起動境界は、Codex が接続方式を選ぶ前に実行する必要があります。`hooks.json` のライフサイクルフックは選択後に動くため、埋め込み会話を後から接続可能にはできません。埋め込み app-server ですでに実行中の Codex プロセスは cmux tree から利用できません。

## Codex app-server の検出

`cmux-tree` はローカルの Codex プロセスを 10 秒ごとに走査します。TCP WebSocket リスナーは `/healthz` で確認し、実行中の Codex デーモンの Unix ソケットも検出します。`r` を押すとすぐに再走査します。

各マシンでは最近の会話 200 件だけを読み込みます。選択した会話では最近の 25 ターンの概要だけを読み込みます。この上限により、大きな Codex アーカイブの全走査と、両方のプロセスで数千件のスレッドや項目を保持することを避けます。

app-server の通知により、実行中のメッセージ、思考、ツール呼び出しを追加リクエストなしでメモリ上に更新します。取りこぼし対策として、軽量な概要を 30 秒ごとに更新します。保存済みツールの詳細は、ユーザーがそのターンの作業アコーディオンを開いた場合だけ取得し、最近の 25 項目に制限します。以前の項目は省略を表示します。保持する各テキスト項目は、軌跡レンダラーの詳細上限と同じ 20,000 文字に制限します。

ローカル TCP リスナーの場合:

```bash
codex app-server --listen ws://127.0.0.1:4500
```

設定しなくても `Local Codex :4500` として表示されます。`codex app-server daemon start` で起動したローカルデーモンも自動的に表示されます。

既定の `stdio://` で起動した Codex app-server は、入出力パイプを親クライアントが所有するため後から接続できません。監視するには WebSocket リスナー、管理デーモン、または `cmux-tree-hook` からの Codex 起動を使います。

`cmux-tree` に永続的な Codex イベントフックは不要です。会話の軌跡は app-server のイベントから直接構築します。会話の監視中にフックコマンドを実行せず、保存済みツール出力もバックグラウンドでは読み込みません。

認証付きリスナーは自動追加されません。探索処理は別プロセスの引数から認証情報を読みません。保護された bearer token ファイルを指定して手動で追加してください。

別のマシンでは、app-server をそのマシンの Tailscale、LAN、または VPN アドレスにバインドします。Codex はループバック以外のリスナーに認証を要求します。

```bash
umask 077
openssl rand -hex 32 > ~/.codex/cmux-tree.token
codex app-server --listen ws://100.64.0.8:4500 \
  --ws-auth capability-token \
  --ws-token-file "$HOME/.codex/cmux-tree.token"
```

トークンを `cmux-tree` を実行するマシンの保護されたファイルへコピーします。マシン追加ダイアログで、リモート WebSocket URL とローカルのトークンファイルのパスを入力します。設定にはトークン本体ではなくファイルのパスだけが保存されます。

`cmux-tree` はネットワークを作成または管理しません。Tailscale、ローカルネットワーク、または別の VPN が提供する任意の経路を利用できます。TLS リバースプロキシで app-server を保護する場合は `wss://` を使います。

Codex は現在 WebSocket app-server トランスポートを実験的機能として扱っています。信頼できるネットワークで使い、ループバック以外のすべてのエンドポイントに capability token を設定してください。

## レイアウトと操作

マシン列には Codex app-server ごとの行が表示されます。会話列は最新のユーザーメッセージまたは停止時刻でルート会話を並べ、親会話の下にサブエージェントのスレッドを表示します。軌跡列は Codex の作業中に更新されます。

完了した作業はターン単位で折りたたまれます。ターンを開くとツール呼び出しと思考が表示され、各項目をさらに開くとコマンド出力、引数、結果、または差分を確認できます。実行中の作業は到着に合わせて展開されます。

| 入力 | 操作 |
| --- | --- |
| `Tab`、`Shift-Tab`、`h`、`l` | 列を変更 |
| `j`、`k`、矢印キー | 選択を移動 |
| `Enter`、`Space` | 展開または折りたたみ |
| `PageUp`、`PageDown`、マウスホイール | スクロール |
| `g`、`G` | 先頭または末尾へ移動 |
| `a` | マシンを追加 |
| `r` | 更新してローカル app-server を再走査 |
| `q`、`Ctrl-C` | 終了 |

マウスで行の選択、軌跡項目の展開、マシン追加ボタンの実行、各列の個別スクロールができます。
