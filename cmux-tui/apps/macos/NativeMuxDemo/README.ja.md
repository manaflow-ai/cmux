# NativeMuxDemo

[English](README.md)

NativeMuxDemo は、cmux リモートデーモン用の独立した SwiftUI クライアントです。
1 つの Iroh/Noise 接続で、公開リソースグラフと複数の
`terminal-bytes-v1` ストリームを転送します。各ターミナルには、独立したローカルの
libghostty エミュレーター、Metal レンダラー、スクロールバック、選択、入力エンコーダー、
ビューポートがあります。

Swift は `GhosttyKit.xcframework` の `ghostty.h` C ABI を `GhosttyKit`
モジュールとしてインポートします。AppKit は各永続 `NSView`、フォーカス、ライフサイクルを
管理し、libghostty はターミナルの動作と描画を管理します。上流 Ghostty の Swift ビューは
実装の参考になりますが、Ghostty のアプリデリゲート、設定、メニュー、コントローラーグラフに
依存します。そのため、この独立クライアントは、それらのアプリソースをパッケージとして
使用せず、`GhosttyKit` を直接呼び出します。Rust は Iroh、Noise、ストリームのフレーム化、
順序付きレンダラーイベントを管理します。ネイティブフロントエンドのビルドでは
`ghostty-vt` を除外するため、PTY 出力は Swift がホストする `GhosttyKit` サーフェスで
1 回だけ解析されます。

このデモは、ワークスペースを縦タブ、スクリーンをスペース、ビューポートカラムを横方向に
スクロールする niri レイアウトとして表示します。また、再帰分割、スタックペイン、
ターミナルまたはブラウザーのコンテンツを縦のペインタブとして表示します。ペイン操作は
`cmux.protocol/2` を使用して、各レイアウト形式を作成し、フォーカスします。

cmux リポジトリのルートから実行します。

```bash
cmux-tui/apps/macos/NativeMuxDemo/run-demo.sh
```

このワークツリーをすでにビルドした場合は、成果物を生成せずに、既存のアプリとデーモンの
バイナリを再利用できます。

```bash
cmux-tui/apps/macos/NativeMuxDemo/run-demo.sh --reuse-build
```

独立アプリバンドルは、ワークツリー内の
`cmux-tui/target/native-mux-demo/NativeMuxDemo.app` にあります。

ランチャーは現在のワークツリーをビルドし、分離した一時デーモンを起動して、代表的な
レイアウトを作成します。その後、2 つの独立した Iroh クライアントを左右に開きます。
左側では NativeMuxDemo が Swift/AppKit と GhosttyKit を使用し、右側では Ghostty が通常の
`cmux-tui connect` フロントエンドを使用します。各クライアントは、個別の 1 回限りの招待と
デバイス ID を取得します。どちらかのフロントエンドに入力すると、両方に同じ PTY 出力が
表示されます。各ビューポートは独立してスクロールできます。どちらかのクライアントを閉じても、
共有 PTY は終了しません。

Ghostty クライアントを省略するには、`--swift-only` を指定します。一方のクライアントが
デタッチしても、もう一方はセッションを継続して使用できます。ランチャーは、分離デーモンを
停止し、作成したすべてのターミナルを閉じてから一時状態を削除します。そのため、永続
ターミナルホストと PTY はデモ終了後に残りません。

再利用可能な成果物に対するライフサイクル回帰テストを実行します。

```bash
cmux-tui/apps/macos/NativeMuxDemo/verify-demo-lifecycle.sh
```

検証スクリプトは実際の Swift 専用デモを起動してアプリを閉じます。新しいターミナルホスト
プロセスが残ると失敗します。ランチャーは、デーモンを起動する前に、作成するレイアウトに
必要な 8 個の空き PTY が macOS にあることも確認します。

デーモンと PTY を別の Apple シリコン Mac で実行し、ネイティブフロントエンドだけを
ローカルで実行することもできます。

```bash
cmux-tui/apps/macos/NativeMuxDemo/run-remote-demo.sh cmux-lawrence
```

リモートランチャーはホストのアーキテクチャを確認し、このワークツリーの正確な
`cmux-tui` バイナリを一意の `/tmp` ディレクトリにコピーします。その後、Iroh デーモンを
起動し、リモートターミナルを 1 つ作成して、1 回限りの招待を SSH だけで転送します。
既存のデモを開いたままにし、LaunchServices がプロセスを混同しないように、ローカルアプリの
一時コピーには一意のバンドル ID とアドホック署名を設定します。ローカルアプリが招待を取得し、
リモートの所有者ソケットがその招待だけを承認します。アプリを閉じると、リモートターミナルを
閉じて、両側の一時状態を削除します。最後のウインドウを閉じた場合も同じ処理をします。
macOS が通常ウインドウのないアプリプロセスを残す場合でも、この処理をします。ランチャーは
リモートホストにインストール済みの `cmux-tui` を置き換えません。一部の SSH アカウント
ラッパーは、コマンドの実際の状態に関係なく成功を返すため、各リモートコマンドの終了状態は
フレーム化した標準エラーレコードで転送します。

リモート起動とクリーンアップを 3 回実行します。

```bash
cmux-tui/apps/macos/NativeMuxDemo/verify-remote-demo-lifecycle.sh cmux-lawrence 3
```
