Goal: **next-code-shrinks**. Leo: "every Rust port deleting the Swift it replaces so the size only goes down".

## What

`DaemonCommandScope` (CmuxNextDaemon/Connection) now runs on cmux-daemon-conn-core's `Scope` (`src/scope.rs`) through `cmux_daemon_scope_new/_call/_free`. The Rust side already existed and wasn't wired in. These parts are Rust's now:

- tickets (`begin`/`end`)
- the stage log, with the 16-entry head kept and a 48-entry cap
- failures
- created objects, deduplicated
- barriers (the max per machine)
- `close`
- the derived idempotency ids (SHA-256 in the UUIDv4 layout)

This PR deletes the Swift copies:

- the `State` struct and its logic
- `appendKeepingHead`
- the CryptoKit `derivedUUID`

These stay in Swift:

- the public API, unchanged
- the idle waiters (`CheckedContinuation`s)
- the clock, sent to Rust as `at_ms`

`end` and `waitUntilIdle` ask the scope under the same Swift lock that holds the waiters. A wake is never lost, the same as before.

No Rust changes. Before porting, I read both sides and the semantics match:

- stamp format `stage@ms`, plus `open#N label` and `close#N label`
- the `open now: #…` tail
- `begin` returns nil once the scope is closed
- `end` ignores an unknown ticket
- an empty key counts as no key
- the derivation string `cmux-next/{kind}/{ordinal}/{key}`

`scripts/cmux-next/ffi-caller-baseline.txt` drops the 4 conn-core functions that now have a Swift caller.

## Size

DaemonCommandScope.swift goes from 11,864 B to 11,725 B: **139 B of Swift deleted** (+84/−101 lines in this file). The deletion is small because the JSON glue to the C ABI costs about as much as the rules it replaces. Most of Connection's Swift is I/O, and that stays in Swift.
