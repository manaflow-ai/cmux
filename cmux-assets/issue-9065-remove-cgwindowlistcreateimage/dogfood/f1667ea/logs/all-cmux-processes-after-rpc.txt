# Bug: Sidebar becomes unclickable when CLI tools emit frame-by-frame spinner characters

## Summary

CLI tools like `pnpm` and other Node/Go/Rust spinners update the terminal title on every animation frame with Unicode braille spinner characters (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`). cmux forwards every title change through `ghosttyDidSetTitle` into the workspace panel-title coalescer and the toolbar command-text updater. The volume of redundant updates thrashes the sidebar's main-thread layout, and click events get swallowed — the sidebar becomes entirely unresponsive to the mouse, requiring keyboard shortcuts to switch workspaces or panels.

## Repro

1. Open a workspace in cmux on macOS 15 or 26.
2. In the terminal, run any command that emits a spinner-updating title:
   ```bash
   pnpm install
   # or: npm install, yarn install, cargo build (with progress), etc.
   ```
3. While the install is running, try to click a different workspace in the sidebar, or click a different tab.

## Expected

Sidebar clicks register immediately; user can switch workspaces/tabs while a spinner is active.

## Actual

Sidebar clicks are swallowed. User must use keyboard shortcuts (`cmd+1`, `cmd+2`, etc.) to navigate until the spinner-emitting command finishes.

## Environment

- cmux: 0.64.14 (and earlier)
- macOS: 15.x and 26.x
- Shell: zsh with stock shell-integration
- Tools confirmed: `pnpm`, generic Unicode-braille spinners

## Root cause

`GhosttyTerminalView.swift` posts `ghosttyDidSetTitle` on every title action from ghostty, including frame-by-frame spinner updates. `TabManager.enqueuePanelTitleUpdate` then enqueues every change through `panelTitleUpdateCoalescer`, and `WindowToolbarController.scheduleFocusedCommandTextUpdate` runs on every post — even when the title didn't meaningfully change. The coalescer caps throughput but the resulting panel-title and toolbar-text mutations still flood the main thread enough that hit-testing clicks get starved.

## Proposed fix

1. Strip leading spinner glyph + interstitial whitespace from terminal titles before posting `ghosttyDidSetTitle`, so frame N and frame N+1 with the same non-spinner text collapse to the same title.
2. Dedupe identical posts at the `TerminalSurface` level via `lastPublishedTerminalTitle`.
3. In `TabManager.enqueuePanelTitleUpdate`, early-return when the pending queue already holds the trimmed title, or when `Workspace.alreadyReflectsPanelTitleUpdate` says the workspace UI already shows it.
4. In `WindowToolbarController`, only schedule a command-text update when the title change is for the currently selected tab.

## Scope notes

This issue is narrowly about the sidebar-freeze regression. It does not cover:

- Workspace pull-request poll throttling on `shellPrompt` (separately optimizable).
- Two-line prompt header redraw on startup resize (Powerlevel10k) — separate display bug.
- Scrollback replay idle-prompt block accumulation — separate scrollback bug.

These were bundled into a single commit on a fork branch but are logically independent and should be filed separately.
