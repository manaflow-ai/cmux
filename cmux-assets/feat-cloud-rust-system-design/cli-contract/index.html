cmux Cloud · Rust CLI · design contract

One CLI, one resource graph, a hard Mac boundary

A Claude process in a Cloud VM can control its leased workspace, use declared project peers, and operate VM files, diffs, Markdown, video, desktop, and browser surfaces. It cannot start a Mac connection or name a Mac resource.

VM owns remote state

Workspace, tab, pane, terminal, browser, and viewer resources live in the VM daemon. One lease starts with one workspace.

Mac renders a projection

The Mac can mirror one remote workspace inside one host-attached container. The VM never gets its local IDs.

Peers use named services

Same-project application services are declared. Shell, exec, transfer, raw ports, and cross-project access need exact grants.

Assume VM root is hostile

Mac denial, peer admission, model authority, and destination rules run outside the VM.

Trust boundary

Assume every process in a VM has root. The guest authority is one machine, daemon session, lease, explicit workspace set, project-root file grant, effect limits, peer grants, generation, nonce, and expiry. The host starts the authenticated circuit and never exposes its local cmux socket.

Fail closed

A guest with no VM daemon or no matching lease gets transport.unavailable or scope.denied. It never tries a host socket or a local fallback.

Internet trade-off

The default project policy has no public Internet. If a user enables internet, cmux still blocks known Mac routes and identities, but it cannot prove that an unrelated public address is not a user device.

Remote control without host control

The user attaches one remote workspace to one local projection container. That container can be a dedicated Cloud workspace or a bounded pane subtree. The guest controls the remote layout. The host owns placement around the container.

Host attaches. The Mac selects the machine, remote workspace, local destination, and presentation policy.

Guest arranges. Claude creates, moves, reorders, focuses, attaches, or detaches VM tabs, panes, and surfaces.

Host reconciles. Revisioned VM events update only descendants of that projection container. Layout mirrors by default. Guest focus does not.

Host stays authoritative. A new guest workspace appears in the Cloud tree but does not open on the Mac. The guest cannot move the container or change Mac focus.

The host can enable follow-focus for one container. It can select only a descendant and cannot activate another Mac window or take keyboard focus. Host input stays bound to one projection ID, remote surface ID, and input epoch. Guest focus cannot retarget it. Closing or replacing the target drops later input. Guest open, diff, markdown open, and browser open use familiar placement rules inside the VM workspace and return durable VM resource IDs even when no host is attached.

Every projected surface keeps host-owned machine and project identity outside the VM frame. Remote content cannot cover it. Host autofill, password managers, clipboard, drag and drop, automatic audio, and global input are disabled.

Typed text enters the VM

Text sent to the selected projection is visible to VM root. The input lease stops hidden retargeting, but it cannot protect a secret after the user sends it.

Command contract

Use noun-first verbs. The authenticated daemon handshake selects guest context. A flag or environment variable cannot select it. The parser hides host commands, and the daemon checks the action again. The guest command policy is the complete allowlist.

cmux pane <pane> split
cmux cloud vm <machine> pane <pane> split
cmux cloud pane <globally-typed-pane-id> split

The cloud prefix changes graph resolution and transport. Resource suffixes stay the same. Typed IDs can omit ancestors. Names and current need the full parent path. Use show for one resource. get is a migration alias.

Every atomic action has a complete effect set. Every command has one primary shape: result, receipt, operation, stream, interactive, or transfer. The local action registry drives help and authorization. It is not a user-facing capabilities command. Independent daemon, projection, and network deny rules stop one bad registry entry from widening authority.

Result

One bounded read. It leaves no hidden work.

Receipt

A committed mutation with stable IDs, revision, and idempotency record.

Operation

Long work with an ID, progress, wait, watch, cancel, and recovery.

Stream or interactive

Cursor and gap rules for events, or an explicit input lease and detach rule.

Transfer

Direction, path grants, digest, byte limit, progress, and final receipt.

Files, diff, Markdown, video, and desktop

File viewer

Canonicalize against the VM project grant. Reject traversal, unsafe symlinks, host paths, and oversized payloads. Send a bounded immutable snapshot.

Diff viewer

Send structured hunks and blob hashes. It is read-only. An edit uses a separate process action in the VM.

Markdown viewer

Render an inert model. Block scripts, active HTML, remote subresources, custom schemes, and host file access.

Media viewer

Decode in a bounded VM process or send VM-rendered frames. Remote video starts muted. Only the local user can enable host audio.

Desktop viewer

Frames are replies on a host-started circuit. Frame-bound input returns to the VM. The VM never receives Mac screen, camera, microphone, or accessibility data.

Local file rule

A remote agent cannot request a Mac picker or receive a host file handle. The user may choose one file, the host scans and bounds it, and an expiring guest path plus digest is sent to the VM. A VM file reaches the Mac only after a host-started pull with a selected destination. A directory mount is not part of the first release.

user selects local file
  → host creates one-time transfer grant
  → VM receives guest path + digest
  → Claude opens the VM copy
  → lease expiry revokes the grant

Browser network policy

The local cmux pane is a pixel and input viewer. It is never a Mac WebView that loads the remote URL. The browser process, DOM, JavaScript, cookies, storage, downloads, and network stack stay in the VM.

cmux browser open http://127.0.0.1:3000
cmux browser <id> snapshot --interactive
cmux browser <id> click <selector-or-ref>
cmux browser <id> fill <selector-or-ref> "query"
cmux browser <id> wait --text "Done"
cmux browser <id> screenshot

Snapshots return element references bound to one document and frame revision. Click, fill, press, select, wait, get, find, and state checks are the normal agent path. Stale references fail. Pointer input and JavaScript remain VM-only fallbacks.

cmux cloud network egress <session> set internet --ttl 1h --domain example.com

A denied public navigation returns that exact host action. The VM cannot approve it. The user changes the lease, then the agent retries. Nothing widens access automatically.

Apply the check before every redirect, subresource, WebSocket, WebRTC, DNS result, and download. A VM-local peer broker combines each grant with source machine identity outside guest control. No portable peer bearer enters the VM. Peer reachability does not give another VM's cmux authority.

Domains and publication

Keep the established Ben Swerdlow domain verbs, defaults, output order, DNS checklist, and access flow. A domain is a host control-plane publication resource, not a port-open alias. A VM agent cannot publish, change access, or remove it.

cmux cloud domains list
cmux cloud domains zones
cmux cloud domains verify example.com
cmux cloud domains publish <vm> <port> --domain app.example.com --access team --team <team-id>
cmux cloud domains access app.example.com public
cmux cloud domains rm app.example.com

Discover. List owned domains and available zones. Generated names skip customer DNS proof.

Verify. The first call prints a labelled DNS checklist. Run the same verb again after the user changes DNS.

Publish. Bind one verified hostname to one VM port and choose personal, team, or public access.

Use. Human output starts with the URL. Protected viewers show sign-in or denial.

Remove. rm takes the hostname and removes the route and certificate binding in one no-prompt migration command.

A publication maps one hostname to one VM port at the managed edge. It never creates a route to the Mac.

Secure 80/20 build target

This path covers normal remote agent work from a clean npm or PyPI install. Headless work does not require the desktop app. Projection is an optional host view:

cmux auth login
cmux cloud vm list
cmux cloud vm create                 # returns ready machine, session, and workspace IDs
cmux cloud session <returned-session> attach
cmux workspace create --name task
cmux run -- bun test
cmux open ./README.md
cmux diff --repo .
cmux browser open http://127.0.0.1:3000
cmux peer list
cmux coderouter run claude
disconnect -> reconnect -> cmux vm pull -> cmux cloud vm <machine> destroy
Fast create

Claim a clean, single-claim warm machine that has never had a tenant. Destroy it after that tenant releases it. Target p50 under 3 seconds and p95 under 10 seconds to daemon-ready. A cold path returns an operation immediately.

Reconnect

Keep VM sessions and viewer state durable. Resume by event cursor or request a bounded snapshot. Never spawn a replacement shell silently.

Revoke

Session revoke or machine destroy invalidates projection bindings, input leases, browser streams, transfer grants, and peer grants.

No discovery ceremony

Use local --help --json, context, action-specific state, and typed errors. Do not add a Cloud capabilities command.

Deliberate first-release limits

Do not ship host browser handoff, recursive host mounts, mixed local and remote layout control, implicit clipboard transfers, profile import, or raw host socket relays. These features add a host data channel before the resource contract is safe.

Included in the same release

Auth, team context, fast VM lifecycle, base and snapshots, SSH and exec, transfer, sessions, remote topology, safe viewers, VM browser and desktop, private networking, VPN, VM peers, CodeRouter, agents, events, public ports, and the exact custom-domain flow are release work. The 80/20 path sets implementation order. It does not remove parity scope.
