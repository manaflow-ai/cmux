cmux Cloud · Rust CLI · design contract

One command surface, two trust domains

A Claude process in a Cloud VM can operate its leased cmux workspaces and viewers. It can show those resources on the Mac through a narrow projection stream. It cannot read or control the Mac.

Boundary Verbs Viewers Browser network Domains Code reuse Build
VM owns remote state

Workspace, tab, pane, terminal, browser, file, diff, and Markdown resources live in the VM daemon. The lease limits the agent to one task scope.

Mac renders a projection

The Mac reconciles remote events into a dedicated Cloud workspace. A projection is not a shared folder, host browser, or host socket.

Host actions stay explicit

Only the user can attach, move, or detach a projection, or pull a selected VM file to a selected local destination.

Trust boundary

Assume every process in a VM is compromised. The only inbound authority is a lease for a machine, session, and remote workspace. The host starts the authenticated outbound stream and never exposes its local cmux socket.

Command contract

Use familiar noun-first verbs. The same Rust protocol models power the standalone packages, the desktop app, and the in-VM client. Host-only placement options are separate from guest topology.

Guest commandEffectResult

A remote move emits a revisioned event. The host moves only the matching remote projection. It never moves a local tab or pane.

Files, diff, Markdown, and desktop

File viewer

Canonicalize against the VM project grant. Reject traversal, unsafe symlinks, host paths, and oversized payloads. Send a bounded immutable snapshot.

Diff viewer

Send structured hunks and expected blob hashes. A click or edit returns to the VM repository. The Mac does not open the path.

Markdown viewer

Render an inert model. Block scripts, active HTML, remote subresources, custom schemes, and host file access.

Desktop viewer

VNC or noVNC frames travel VM to Mac. Input is explicit Mac to VM. The VM never receives Mac screen, camera, microphone, or accessibility data.

Local file rule

A remote agent cannot request a Mac picker or receive a host file handle. The user may choose one file, the host scans and bounds it, and an expiring guest path plus digest is sent to the VM. A directory mount is not part of the first release.

user selects local file
  → host creates one-time transfer grant
  → VM receives guest path + digest
  → Claude opens the VM copy
  → lease expiry revokes the grant

Browser network policy

The local cmux pane is a pixel and input viewer. It is never a Mac WebView that loads the remote URL. The browser process, DOM, JavaScript, cookies, storage, downloads, and network stack stay in the VM.

DestinationDefaultRule
VM loopback and assigned interfacesAllowUsed for local servers and the VM desktop.
VPC peerDenyAllow only an exact machine, IP, port, and protocol grant.
Public internetDenyEnable only with an explicit machine or team internet policy.
Mac gateway, LAN, link-local, metadata, unscoped private rangesDenyBlock after canonicalizing IPv4, IPv6, mapped, integer, and DNS forms.

Apply the check before every redirect, subresource, WebSocket, WebRTC, DNS result, and download. VPC reachability gives network access only. It does not give another VM's cmux authority.

Domains and publication

Keep the established Ben Swerdlow domain verbs and order. A domain is a publication resource, not a port-open alias.

cmux cloud domains list
cmux cloud domains zones
cmux cloud domains verify example.com
cmux cloud domains publish <vm> <port> --domain app.example.com --access team --team <team-id>
cmux cloud domains access app.example.com public
cmux cloud domains rm app.example.com

Discover. List owned domains and available zones. Generated names skip customer DNS proof.

Verify. The first call prints a labelled DNS checklist. Run the same verb again after the user changes DNS.

Publish. Bind one verified hostname to one VM port and choose personal, team, or public access.

Use. Human output starts with the URL. Protected viewers show sign-in or denial.

Remove. rm takes the hostname and removes the route and certificate binding in one no-prompt migration command.

Build target

This page is the implementation target. The first complete path should work from a clean npm or PyPI install and does not require the desktop app:

cmux auth login
cmux cloud vm list
cmux cloud vm create
cmux cloud session attach <session>
cmux workspace create --name task
cmux open ./README.md
cmux diff --repo .
cmux browser open http://127.0.0.1:3000
cmux coderouter status
disconnect → reconnect → cmux vm pull → cmux cloud vm destroy
Fast create

Claim a scrubbed warm machine. Readiness means the daemon, private route, and initial workspace lease are usable.

Reconnect

Keep VM sessions and viewer state durable. Resume by event cursor or request a bounded snapshot. Never spawn a replacement shell silently.

Revoke

Session revoke or machine destroy invalidates projection bindings, input leases, browser streams, transfer grants, and peer grants.

Deliberate first-release limits

Do not ship host browser handoff, recursive host mounts, mixed local and remote layout control, implicit clipboard transfers, or raw host socket relays. These features add a host data channel before the resource contract is safe.
